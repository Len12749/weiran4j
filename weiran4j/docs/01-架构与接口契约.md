# weiran4j 架构与接口契约（v2 重写）

> 本文是架构、数据与跨接口业务约束的事实源。HTTP 路径、方法、参数和请求/响应 schema 以 Springdoc 从 Controller 声明生成的 OpenAPI 为唯一事实源；本文不重复列出这些接口定义。
>
> 重写的三条前提（D-008）：
> 1. **不再兼容 PHP weiran-v1**：不读写 `pam_*` 表，不保留历史密码算法，不保留 `/api/v1` 前缀。
> 2. **去掉 wuli3 底座**：直接基于 Spring Boot 3.5 + MyBatis-Plus + Flyway，clone 即可构建。
> 3. **能力对标 mono4ts 的「标准后台底座」**：登录/JWT、用户、角色、菜单（动态路由 + 按钮权限）、部门、
>    字典、系统配置、登录日志、操作日志；前端 Semi Design 后台布局。

## 2. Gradle 模块

```
weiran4j/
├── build-logic/                 # 约定插件（质量门禁唯一来源）
├── weiran-dependencies/         # BOM：import spring-boot-dependencies + mybatis-plus-bom，钉 jjwt/springdoc/testcontainers 版本
├── weiran-framework/            # 框架层（D-016 并入原 weiran-common）：
│                                #   纯 Java 契约包 error / page / response / status / text / tree（ErrorCode / BizException / CommonErrors / PageQuery / PageResult / ApiResponse）
│                                #   + Spring 基础设施（替代 wuli3）：统一响应、全局异常、认证拦截、权限注解、操作日志切面、MyBatis-Plus 配置
├── weiran-system/               # 后台基座（DDD 五层，D-011 由 system + platform 合并而来）
│   └── weiran-system-{api,domain,application,infrastructure,adapter}
│       ├── com.weiran.system.*    # 身份与权限：auth / user / role / menu / department / login-log
│       └── com.weiran.platform.*  # 平台能力：dict / config / operation-log
└── weiran-app/                  # 启动模块：只聚合依赖 + application.yml + 集成测试
```

依赖方向：`adapter → application → domain`，`infrastructure → domain`，`application → api`。
所有层都依赖 `weiran-framework`，但它的 Spring / MyBatis-Plus 依赖是 `implementation`、不向下游传递（D-016）：
**domain 与 api 只能用它的纯 Java 契约包**（编译期本来也看不到框架类型）；application / infrastructure / adapter 用到哪个框架库自己声明。

各层职责：

| 层 | 放什么 | 禁止 |
| --- | --- | --- |
| api | 对外 DTO（record）、应用服务接口、命令对象 | Spring、MyBatis |
| domain | 聚合/实体/值对象、领域规则、仓储端口（接口） | 任何框架 |
| application | 实现 api 的服务接口，编排用例，`@Transactional` 边界 | `*DO`、Mapper |
| infrastructure | `*DO`、Mapper、仓储实现、JWT、BCrypt、Flyway 脚本 | Controller |
| adapter | `@RestController`、请求 DTO 与校验、`@RequiresPermission`、`@OperationLog` | 直接调 Mapper |

每个模块用 `@AutoConfiguration` + `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`
自我登记；Mapper 用 `@MapperScan` 写在该模块 infrastructure 的自动配置里。`weiran-app` 不写 `@ComponentScan`。

## 6. HTTP API 与跨接口业务约束

HTTP 接口的路径、HTTP 方法、参数、请求体、响应 schema 与接口级权限声明，以 Controller / DTO 声明生成的 OpenAPI 为准。不要在本文维护接口清单或重复 OpenAPI 已能表达的接口字段；本节只记录 OpenAPI 难以完整表达、需要前后端共同遵守的跨接口行为与业务规则。

- OpenAPI JSON：`/v3/api-docs`；Swagger UI：`/swagger-ui.html`。两者仅在 `local` profile 开启。
- 路由命名约定见 [`openspec/rules/advisory/api-design.md`](../../openspec/rules/advisory/api-design.md)：`/api-{type}/{module}/...` 是登录后入口，`/api-{type}/n/{module}/...` 是未鉴权入口。当前 `type=backend`；新增 `type` 须同步认证拦截器及开发、部署代理。
- 写操作按业务需要使用 `@OperationLog`；权限仍以 `sys_menu` 中的按钮权限码为准。
- 错误响应的 `code` 为六位数字，依次为服务号、资源号、错误号（各两位）；框架通用为 `10`、system 为 `11`、区划为 `12`。HTTP 状态由错误定义的 `httpStatus()` 独立决定；成功响应的 `code` 仍为数字 `0`。
- 管理列表默认按 ID 降序并保证跨页稳定；树形列表保留父子层级，同级按 ID 降序。前端表格至少保留一列弹性列并填满内容区。

### 6.1 认证与账号行为

- 浏览器认证使用 HttpOnly Cookie `weiran_token`（`Path=/api-backend`）与非 HttpOnly `weiran_csrf`；写请求携带 `X-CSRF-Token`。脚本登录可通过 `X-Auth-Mode: token` 选择响应体令牌模式，并在后续请求使用 Bearer。`/api-backend/{module}/**` 要求登录并校验声明的权限；`/api-backend/n/{module}/**` 不做用户授权。外部登录发起与回调走后者，外部账号绑定发起走前者。
- 用户名不存在与密码错误统一返回 `110101`，防止账号枚举；禁用账号返回 `110103`。成功或失败的密码登录均写入 `sys_login_log`，成功后更新最后登录时间和 IP。
- 手机号验证码登录由系统配置开关、已启用的短信发送器和当前模式的有效验证码模板共同控制；`local` 模板须包含 `${code}`，发码时替换为 6 位验证码并记录渲染后的正文。验证码 5 分钟有效、一次性使用，按手机号与客户端 IP 限制发送和登录尝试。验证码只保存在单实例进程内存中，应用重启会失效；多实例部署需将挑战与限流迁移到共享存储。发码前查询账号：未绑定手机号返回 `110106`「手机号不存在」，账号已禁用返回 `110107`「手机号已禁用」；短信发送失败也返回错误，只有实际发送或本地日志记录成功才返回成功。登录时手机号不存在、验证码错误统一返回 `110101`，成功与失败登录均写入 `sys_login_log`，日志中的手机号脱敏。
- 密码修改、管理员重置密码、禁用账号时递增 `sys_user.token_version`；每次请求查库验证 JWT 的 `ver`，不使用缓存吊销令牌。
- 外部身份只通过 `(provider, external_id)` 映射用户，不按用户名关联。未绑定身份由提供方的 `auto-provision` 决定拒绝或自动开通；自动开通用户没有本地密码。提供方支持 OIDC 与 CAS，配置方式见 [`02-部署.md`](02-部署.md) §5a。
- `weiran.auth.password-login.enabled=false` 时仅内置超管可用密码登录。JWT 使用 HS256，默认有效期 12 小时；`iss` 缺失或不匹配、`aud` 不包含本系统、密钥缺失或短于 32 字节时分别按认证失败或启动配置错误处理。部署配置见 [`02-部署.md`](02-部署.md)。
- 外部身份登录签发本地 JWT。绑定模式要求已登录；未设置本地密码且只剩最后一个外部身份时不能解绑，以避免账号锁死。

### 6.2 用户资料与个性化数据

- 用户名、非空手机号、非空邮箱在用户之间全局唯一；写入前去除首尾空白，手机号和邮箱可为空，空值统一保存为 `NULL`。唯一性检查由应用层执行，数据库唯一索引负责并发兜底；邮箱比较遵循 `sys_user.email` 列的 MySQL collation。
- 管理员可单独修改用户名、手机号或邮箱，一次请求只更新其中一个字段；与用户创建、管理员编辑、本人的资料编辑及外部身份自动开通共用上述唯一性约束。
- 用户查询的组合筛选条件取交集；用户名、昵称、手机号关键词查询按模糊匹配。创建时间与最后登录时间采用闭区间；只传一端时按该端过滤，最后登录筛选会排除从未登录的用户。
- 用户资料不得暴露密码或令牌版本。自动开通的外部身份用户没有本地密码。
- 菜单服务返回当前用户可见的菜单树；`visible=false` 的菜单仍参与前端路由注册，只从导航显示中隐藏。超管获得全部权限，权限集合为 `[*]`。
- 用户偏好保存为 JSON 全量覆盖，最大序列化长度 16 KiB；收藏菜单去重并保留首次顺序，最多 50 个，只接受当前用户可访问的启用菜单。偏好与收藏保存不刷新 `sys_user.updated_at`，偏好写入不记操作日志。
- `sys_user` 响应不暴露 `password` 和 `token_version`。MySQL JSON 可能重排对象键，调用方不得依赖偏好对象的键顺序。

### 6.3 字典与系统配置

- 字典与配置分组共享 `sys_group`，通过 `type=dict` 与 `type=config` 隔离；配置分组再以 `group_key=config_system/config_sms` 分域。同一 `code` 可在不同配置域复用。字典读写只作用于 `dict` 组；配置只能引用对应域中启用的组。数据库字段为 `sys_dict_item.group_id`。
- `sys_config.config_key` 遵循 `{range}.{group}.{value}`：`range` 为 `system` 或 `sms`，`group` 为配置所属的 `sys_group.code`，`value` 是组内配置项编码；三段使用小写字母、数字、下划线或连字符，组名与配置项编码以小写字母开头。新建配置与修改配置键或分组时必须遵守；已有不符合约定的自定义键保留读取与原位改值能力。
- 系统配置分组列表提供创建时间、内置状态和可删除状态；仅空的自定义配置分组可删除，内置或包含配置项的分组不可删除。
- 配置键必须使用 `system.` 或 `sms.` 前缀；内置配置键不可修改，内置配置不可删除。匿名配置读取仅允许 `system.general.title`，不会因此自动在前端展示。
- 配置页展示行为、字段元数据与配置组种子见本文件的数据和菜单约束；配置接口的具体动作与字段以 OpenAPI 为准。

### 6.4 行政区划业务规则

- 区划代码以字符串保存并保持唯一，创建后不可修改；父级必须存在、层级正确且不能形成循环。删除仍有子级的节点返回冲突。
- 行政区划树关键词命中后代时保留祖先。管理树同级按 ID 倒序；供选择器使用的结果只包含启用节点及其启用祖先，并按 `sort`、`code` 升序。
- CSV 导出覆盖全部匹配记录，不受页面展开状态影响。Java 调用方可通过 `RegionLookupService.enabledTree()` 获取启用地区树。
- 业务错误码为 `120101`（父级/层级关系无效）、`120102`（区划代码重复）、`120103`（删除节点仍有子级）；服务号 `12`、资源号 `01` 登记在 [`business-modules.md`](business-modules.md)。

### 6.5 应用内短信服务

system 向业务模块提供 Java 服务 `com.weiran.system.api.sms.SmsService`：调用方提交手机号、短信模板 CODE 与模板参数，获得 `SENT`、`LOGGED`、`NOT_CONFIGURED`、`RATE_LIMITED`、`INVALID_NUMBER` 或 `FAILED` 结果。发送模式默认为 `disabled`，也可显式选择 `local` 或 `aliyun`；`local` 会记录模板代码与参数供开发联调，须限制日志访问与保留时间。短信配置与系统配置是独立页面，复用 `sys_config` 存储；配置键按 `{range}.{group}.{value}` 命名，短信使用 `sms` 范围与 `sys_group.group_key=config_sms`：签名为 `sms.general.sign_name`，本地与阿里云验证码模板分别为 `sms.system_tpl.captcha_local`、`sms.system_tpl.captcha_aliyun`。此能力不是 HTTP 接口；system 不负责验证码生成、校验与发送频率策略，调用方须按业务需要处理。

## 7. 前端（`web/`，仓库根目录）

对标 mono4ts `packages/web` 的**骨架**，不搬业务组件。

