# weiran4j 架构与接口契约（v2 重写）

> 本文是架构、数据与跨接口业务约束的事实源。HTTP 路径、方法、参数和请求/响应 schema 以 Springdoc 从 Controller 声明生成的 OpenAPI 为唯一事实源；本文不重复列出这些接口定义。
>
> 重写的三条前提（D-008）：
> 1. **不再兼容 PHP weiran-v1**：不读写 `pam_*` 表，不保留历史密码算法，不保留 `/api/v1` 前缀。
> 2. **去掉 wuli3 底座**：直接基于 Spring Boot 3.5 + MyBatis-Plus + Flyway，clone 即可构建。
> 3. **能力对标 mono4ts 的「标准后台底座」**：登录/JWT、用户、角色、菜单（动态路由 + 按钮权限）、部门、
>    字典、系统配置、登录日志、操作日志；前端 Semi Design 后台布局。

## 2. Gradle 模块

```
weiran4j/
├── build-logic/                 # 约定插件（质量门禁唯一来源）
├── weiran-dependencies/         # BOM：import spring-boot-dependencies + mybatis-plus-bom，钉 jjwt/springdoc/testcontainers 版本
├── weiran-framework/            # 框架层（D-016 并入原 weiran-common）：
│                                #   纯 Java 契约包 error / page / response / status / text / tree（ErrorCode / BizException / CommonErrors / PageQuery / PageResult / ApiResponse）
│                                #   + Spring 基础设施（替代 wuli3）：统一响应、全局异常、认证拦截、权限注解、操作日志切面、MyBatis-Plus 配置
├── weiran-system/               # 后台基座（DDD 五层，D-011 由 system + platform 合并而来）
│   └── weiran-system-{api,domain,application,infrastructure,adapter}
│       ├── com.weiran.system.*    # 身份与权限：auth / user / role / menu / department / login-log
│       └── com.weiran.platform.*  # 平台能力：dict / config / operation-log
└── weiran-app/                  # 启动模块：只聚合依赖 + application.yml + 集成测试
```

依赖方向：`adapter → application → domain`，`infrastructure → domain`，`application → api`。
所有层都依赖 `weiran-framework`，但它的 Spring / MyBatis-Plus 依赖是 `implementation`、不向下游传递（D-016）：
**domain 与 api 只能用它的纯 Java 契约包**（编译期本来也看不到框架类型）；application / infrastructure / adapter 用到哪个框架库自己声明。

各层职责：

| 层 | 放什么 | 禁止 |
| --- | --- | --- |
| api | 对外 DTO（record）、应用服务接口、命令对象 | Spring、MyBatis |
| domain | 聚合/实体/值对象、领域规则、仓储端口（接口） | 任何框架 |
| application | 实现 api 的服务接口，编排用例，`@Transactional` 边界 | `*DO`、Mapper |
| infrastructure | `*DO`、Mapper、仓储实现、JWT、BCrypt、Flyway 脚本 | Controller |
| adapter | `@RestController`、请求 DTO 与校验、`@RequiresPermission`、`@OperationLog` | 直接调 Mapper |

每个模块用 `@AutoConfiguration` + `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`
自我登记；Mapper 用 `@MapperScan` 写在该模块 infrastructure 的自动配置里。`weiran-app` 不写 `@ComponentScan`。

### 2.2 下游扩展入口（D-012）

以 git fork 跟随本仓的下游项目，只在下面这些位置落改动，不修改任何上游文件，同步上游时就不会冲突。
**「下游怎么做」一列里的文件与目录归下游独占，上游永不创建**（`business-modules.md` 例外：上游建好表头，下游只追加行）。

| 扩展什么 | 下游怎么做 | 上游的接入点 |
| --- | --- | --- |
| 业务模块 | 建 `weiran4j/weiran-<mod>/weiran-<mod>-{api,domain,application,infrastructure,adapter}/` 五个目录 | `settings.gradle.kts` 自动发现，写入 `gradle.extra["weiran.businessModules"]`；BOM 坐标与 `weiran-app` 的依赖、覆盖率聚合据此生成。**含任一层却五层不齐时构建失败** |
| 号段登记 | 在 `business-modules.md` 追加一行 | 见 §2.1 |
| 业务默认配置 | 在某个业务模块的 `src/main/resources/` 放 `application-biz.yml`（全应用只能有一份） | `application.yml` 的 `spring.config.import: optional:classpath:application-biz.yml`。它覆盖 `application.yml` 的同名键，但低于 profile 文件（如 `application-local.yml`）与环境变量。**密钥不放这里**，仍走环境变量（CP-9） |
| 第三方依赖版本 | `weiran4j/weiran-dependencies/biz-dependencies.gradle.kts` 登记版本约束、按需 import 第三方 BOM（写法见下）；业务模块照常不写版本 | `weiran-dependencies` 在该文件存在时 apply（D-013）。`weiran-app` 的 `check` 含 `verifyFrameworkVersions`：**下游清单不得约束框架已管理的依赖**（不论高低）；框架依赖被传递拉离框架版本时失败，确认可接受的写进下游白名单并写理由 |
| Flyway 脚本 | 放 `db/migration/<mod>/`（CP-15） | `spring.flyway.out-of-order: true`：上下游脚本时间戳交错时，后到的低版本脚本会被补执行而不是让启动失败。因此**脚本之间不得依赖版本号顺序之外的执行次序** |
| 非 `/api-backend/**` 接口的响应格式 | Controller 类或方法标 `@SkipApiResponse`（见 §3） | `ApiResponseBodyAdvice` 不包 `{code:0}`。异常仍由 `GlobalExceptionHandler`（`LOWEST_PRECEDENCE`）处理，下游可用更高优先级的 `@RestControllerAdvice` 覆盖 |

| 页面 | `web/src/pages/<mod>/**` | `page-registry.ts` 的 glob 自动收集 |
| AI 协作规范 | 仓库根 `AGENTS.biz.md` | `AGENTS.md` 声明存在即必读 |
| 公共组件登记 | `openspec/rules/advisory/components.biz.md`，并在 `AGENTS.biz.md` 的规则索引表登记它 | `components-registry` 守卫把它与 `components.md` 一并当作登记来源；`rules-index` 守卫把 `AGENTS.biz.md` 与 `AGENTS.md` 一并当作索引来源 |
| 现状文档索引 | `openspec/state/bizs/README.biz.md` | `bizs/README.md` 指向它 |

## 6. HTTP API 与跨接口业务约束

HTTP 接口的路径、HTTP 方法、参数、请求体、响应 schema 与接口级权限声明，以 Controller / DTO 声明生成的 OpenAPI 为准。不要在本文维护接口清单或重复 OpenAPI 已能表达的接口字段；本节只记录 OpenAPI 难以完整表达、需要前后端共同遵守的跨接口行为与业务规则。

- OpenAPI JSON：`/v3/api-docs`；Swagger UI：`/swagger-ui.html`。两者仅在 `local` profile 开启。
- 路由命名约定见 [`openspec/rules/advisory/api-design.md`](../../openspec/rules/advisory/api-design.md)：`/api-{type}/{module}/...` 是登录后入口，`/api-{type}/n/{module}/...` 是未鉴权入口。当前 `type=backend`；新增 `type` 须同步认证拦截器及开发、部署代理。
- 写操作按业务需要使用 `@OperationLog`；权限仍以 `sys_menu` 中的按钮权限码为准。
- 错误响应的 `code` 为六位数字，依次为服务号、资源号、错误号（各两位）；框架通用为 `10`、system 为 `11`、区划为 `12`。HTTP 状态由错误定义的 `httpStatus()` 独立决定；成功响应的 `code` 仍为数字 `0`。
- 管理列表默认按 ID 降序并保证跨页稳定；树形列表保留父子层级，同级按 ID 降序。前端表格至少保留一列弹性列并填满内容区。

### 6.1 认证与账号行为

- 浏览器认证使用 HttpOnly Cookie `weiran_token`（`Path=/api-backend`）与非 HttpOnly `weiran_csrf`；写请求携带 `X-CSRF-Token`。脚本登录可通过 `X-Auth-Mode: token` 选择响应体令牌模式，并在后续请求使用 Bearer。`/api-backend/{module}/**` 要求登录并校验声明的权限；`/api-backend/n/{module}/**` 不做用户授权。外部登录发起与回调走后者，外部账号绑定发起走前者。
- 用户名不存在与密码错误统一返回 `110101`，防止账号枚举；禁用账号返回 `110103`。成功或失败的密码登录均写入 `sys_login_log`，成功后更新最后登录时间和 IP。
- 手机号验证码登录由系统配置开关、已启用的短信发送器和当前模式的有效验证码模板共同控制；`local` 模板须包含 `${code}`，发码时替换为 6 位验证码并记录渲染后的正文。验证码 5 分钟有效、一次性使用，按手机号与客户端 IP 限制发送和登录尝试。验证码只保存在单实例进程内存中，应用重启会失效；多实例部署需将挑战与限流迁移到共享存储。发码前查询账号：未绑定手机号返回 `110106`「手机号不存在」，账号已禁用返回 `110107`「手机号已禁用」；短信发送失败也返回错误，只有实际发送或本地日志记录成功才返回成功。登录时手机号不存在、验证码错误统一返回 `110101`，成功与失败登录均写入 `sys_login_log`，日志中的手机号脱敏。
- 密码修改、管理员重置密码、禁用账号时递增 `sys_user.token_version`；每次请求查库验证 JWT 的 `ver`，不使用缓存吊销令牌。
- 外部身份只通过 `(provider, external_id)` 映射用户，不按用户名关联。未绑定身份由提供方的 `auto-provision` 决定拒绝或自动开通；自动开通用户没有本地密码。提供方支持 OIDC 与 CAS，配置方式见 [`02-部署.md`](02-部署.md) §5a。
- `weiran.auth.password-login.enabled=false` 时仅内置超管可用密码登录。JWT 使用 HS256，默认有效期 12 小时；`iss` 缺失或不匹配、`aud` 不包含本系统、密钥缺失或短于 32 字节时分别按认证失败或启动配置错误处理。部署配置见 [`02-部署.md`](02-部署.md)。
- 外部身份登录签发本地 JWT。绑定模式要求已登录；未设置本地密码且只剩最后一个外部身份时不能解绑，以避免账号锁死。

### 6.2 用户资料与个性化数据

- 用户名、非空手机号、非空邮箱在用户之间全局唯一；写入前去除首尾空白，手机号和邮箱可为空，空值统一保存为 `NULL`。唯一性检查由应用层执行，数据库唯一索引负责并发兜底；邮箱比较遵循 `sys_user.email` 列的 MySQL collation。
- 管理员可单独修改用户名、手机号或邮箱，一次请求只更新其中一个字段；与用户创建、管理员编辑、本人的资料编辑及外部身份自动开通共用上述唯一性约束。
- 用户查询的组合筛选条件取交集；用户名、昵称、手机号关键词查询按模糊匹配。创建时间与最后登录时间采用闭区间；只传一端时按该端过滤，最后登录筛选会排除从未登录的用户。
- 用户资料不得暴露密码或令牌版本。自动开通的外部身份用户没有本地密码。
- 菜单服务返回当前用户可见的菜单树；`visible=false` 的菜单仍参与前端路由注册，只从导航显示中隐藏。超管获得全部权限，权限集合为 `[*]`。
- 用户偏好保存为 JSON 全量覆盖，最大序列化长度 16 KiB；收藏菜单去重并保留首次顺序，最多 50 个，只接受当前用户可访问的启用菜单。偏好与收藏保存不刷新 `sys_user.updated_at`，偏好写入不记操作日志。
- `sys_user` 响应不暴露 `password` 和 `token_version`。MySQL JSON 可能重排对象键，调用方不得依赖偏好对象的键顺序。

### 6.3 字典与系统配置

- 字典与配置分组共享 `sys_group`，通过 `type=dict` 与 `type=config` 隔离；配置分组再以 `group_key=config_system/config_sms` 分域。同一 `code` 可在不同配置域复用。字典读写只作用于 `dict` 组；配置只能引用对应域中启用的组。数据库字段为 `sys_dict_item.group_id`。
- `sys_config.config_key` 遵循 `{range}.{group}.{value}`：`range` 为 `system` 或 `sms`，`group` 为配置所属的 `sys_group.code`，`value` 是组内配置项编码；三段使用小写字母、数字、下划线或连字符，组名与配置项编码以小写字母开头。新建配置与修改配置键或分组时必须遵守；已有不符合约定的自定义键保留读取与原位改值能力。
- 系统配置分组列表提供创建时间、内置状态和可删除状态；仅空的自定义配置分组可删除，内置或包含配置项的分组不可删除。
- 配置键必须使用 `system.` 或 `sms.` 前缀；内置配置键不可修改，内置配置不可删除。匿名配置读取仅允许 `system.general.title`，不会因此自动在前端展示。
- 配置页展示行为、字段元数据与配置组种子见本文件的数据和菜单约束；配置接口的具体动作与字段以 OpenAPI 为准。
- 文件选中后立即上传并登记到 `sys_media`；单文件配置保存 URL，多文件配置保存按顺序排列的 URL 数组，移除文件仅修改配置值。资源库从 `sys_config.config_value` 与 `sys_user.avatar` 识别引用位置，仍被引用的文件不得删除。图片在页面内预览，其他文件交给浏览器打开或下载；单文件最大 10 MB，多文件组件默认最多 9 个，满额隐藏上传入口。

### 6.4 行政区划业务规则

- 区划代码以字符串保存并保持唯一，创建后不可修改；父级必须存在、层级正确且不能形成循环。删除仍有子级的节点返回冲突。
- 行政区划树关键词命中后代时保留祖先。管理树同级按 ID 倒序；供选择器使用的结果只包含启用节点及其启用祖先，并按 `sort`、`code` 升序。
- CSV 导出覆盖全部匹配记录，不受页面展开状态影响。Java 调用方可通过 `RegionLookupService.enabledTree()` 获取启用地区树。
- 业务错误码为 `120101`（父级/层级关系无效）、`120102`（区划代码重复）、`120103`（删除节点仍有子级）；服务号 `12`、资源号 `01` 登记在 [`business-modules.md`](business-modules.md)。

### 6.5 应用内短信服务

system 向业务模块提供 Java 服务 `com.weiran.system.api.sms.SmsService`：调用方提交手机号、短信模板 CODE 与模板参数，获得 `SENT`、`LOGGED`、`NOT_CONFIGURED`、`RATE_LIMITED`、`INVALID_NUMBER` 或 `FAILED` 结果。发送模式默认为 `disabled`，也可显式选择 `local` 或 `aliyun`；`local` 会记录模板代码与参数供开发联调，须限制日志访问与保留时间。短信配置与系统配置是独立页面，复用 `sys_config` 存储；配置键按 `{range}.{group}.{value}` 命名，短信使用 `sms` 范围与 `sys_group.group_key=config_sms`：签名为 `sms.general.sign_name`，本地与阿里云验证码模板分别为 `sms.system_tpl.captcha_local`、`sms.system_tpl.captcha_aliyun`。此能力不是 HTTP 接口；system 不负责验证码生成、校验与发送频率策略，调用方须按业务需要处理。

## Data Flow

### 来源与对象

1. 新普通/团体/学校导入作品source_database取当前账号来源；zhongxi派生scoring_scope=ENTRY，qudao/houtai派生PARTICIPANT。中戏每作品一个目标，其余每有效参赛人一个目标；报名和导入仍在原作品组事务内完成。
2. 历史作品以已存source_database为权威，不由成员、学校或渠道名称反推。准备预览按来源核对scoring_scope与目标集合；只有无任务、评分、汇总和奖项引用时可修正，保留旧目标为非ACTIVE并幂等建立正确集合。有引用的冲突明确阻断，不自动迁移评分。
3. 历史正确目标及ID保持；多次准备不得新增重复目标。同作品不允许ENTRY和PARTICIPANT同时作为有效评分集合。团体人员级对象分别显示参赛人，所有写入以targetId而非entryId定位。

### 初审与阶段

- INITIAL为管理员对作品的定性初审，不分配多人评委、不录数字分；通过/驳回、原因、操作者、版本和历史留档。驳回须原因；通过可附意见。
- 每赛事有INITIAL/PROVINCIAL/NATIONAL唯一阶段。省国审配置总分上下限、最低评委数、可空晋级线；数字至多两位，最低人数≥1。阶段状态DRAFT→OPEN→CLOSED→FROZEN；首次OPEN前规则与目标准备完整。
- 初审通过的有效作品对应目标进入省审候选，NATIONAL-only作品不进入省审。阶段关闭立即拒绝评分草稿和提交；FROZEN表示已确认汇总。
- 管理员在未产生下游评分前可带原因重审；已有省国审评分时不可直接撤回初审，需先显式失效相应阶段/下游结果，保留历史。

### 规则与范围

- 评分规则/维度保存不可变revision；维度按阶段+一级赛项管理名称、说明、记录分区间、排序。OPEN后不得原地改规则；需关闭并重开新revision。新的revision不会沿用旧草稿或把旧提交冒充新评分，页面显示待重新评分。
- 评委范围包含userId、competitionId、phaseCode、省/国阶段、一级赛项、可选专业/赛区、enabled。专业/赛区为空为不限；所有外键与父子关系及赛事一致性由服务端核验。
- 管理员业务权限默认覆盖全部赛事，不新造全局赛事/来源ACL；评委只见本人有效assignment，且每次读取/写入核验用户启用、scope匹配、作品/参赛人/目标有效及当前阶段。即使知道他人ID也不可读写。
- 停用范围使匹配任务不可提交，已有提交只保留历史并使相关有效汇总/奖项STALE；范围不能被简单删除来掩盖影响。操作先预览影响并带原因确认。基座用户禁用没有CQT事件回调，本切片不增加事件/worker：每次业务读取、预览和确认通过UserService重新取用户状态及updatedAt，发现禁用或快照变化后惰性使相关结果STALE并拒绝旧预览。与基座禁用并发的请求以本次校验快照为准，下一业务读取重新核验，不承诺跨模块瞬时推送失效。

### 分配与评分

- 手工分配和自动分配都先预览，返回target、reviewer、已有任务、越界/缺人原因、工作量与previewToken。自动分配在合法scope候选中按当前有效任务数、userId稳定排序，补齐每对象指定人数，不重复分配已有有效评委。
- 确认时重验作品、阶段、规则、scope、用户状态和候选版本。存在未覆盖对象须调整范围或显式从候选中移除后重新预览，不默认静默跳过。单次候选≤500目标，总新任务≤5000，超限要求缩小筛选，事务不承接无限全表任务。
- 同阶段同对象同评委唯一；CANCELLED任务可恢复且沿用assignmentId，恢复重验范围。取消已提交任务必须额外管理权限、原因及影响预览，旧评分留档，不再计入有效评分，关联结果STALE。
- 评分状态EMPTY/DRAFT/SUBMITTED；草稿可不完整，提交要求所有启用维度的记录分和评语、独立综合分齐全且在范围内，维度不计算权重、不相加替代综合分。评语trim后非空且≤2000字，分数字段最多两位。
- 请求带expectedVersion，评分写入CAS；当前用户决定reviewerId，不接受客户端替换。开放且未冻结时可修订，旧记录保留revision；相同内容的幂等重试不追加重复修订。未提交草稿不得进入平均分。

### 汇总、复核与晋级

- 管理员关闭阶段后预览汇总。以有效且提交、对应当前规则revision的不同评委综合分计算普通平均，HALF_UP两位。至少达到minimumReviewers才有成绩；无需所有分配评委均提交，预览明确列出待评、缺评和未达最低人数。
- 确认携带输入版本hash，事务锁阶段行，再重验当前评分/assignment/scope/目标/规则版本；所有会改变输入的操作也锁同一阶段行并递增inputVersion。任一漂移409要求重新预览，不基于陈旧快照确认。
- 汇总为本阶段全部当前候选生成确认快照；可确认达标子集，未达最低人数或失效对象仅生成缺评/失效快照并将旧成绩标STALE，不产生有效新final。预览须明确完整达标与跳过清单，管理员显式接受缺评后才能确认并令阶段FROZEN；没有任何达标对象时拒绝确认。用户要补评时需重开再评分汇总。有效最终分与计算快照记录原评分revision和规则revision。
- 成绩管理员仅在FROZEN阶段可带理由更正有效最终分，不修改评委原始分；更正记录前后值与操作者，生成新finalVersion，使相关已确认奖项批次STALE并保留原奖项历史。需重新预览评奖才能形成新有效奖项。
- 重开阶段必须原因与影响预览；使该阶段及依赖它的晋级/下游已生成结果失效待复核，不删除历史。FROZEN阶段不接受直接评分；重开后显式处理旧final/award状态。
- 晋级状态ELIGIBLE/ADVANCED/ELIMINATED/LOCKED，独立于计算状态，重算不得把人工决定悄悄重置。阈值仅产生建议名单，管理员确认后才晋级；人工决定必须原因。前置最终成绩失效时晋级标待复核，不继续推进。
- SHARED赛事确认晋级后将同一target纳入国审；SEPARATE只生成资格，绝不复制作品或绕过独立报名。已有合法NATIONAL/BOTH作品可由管理员关联资格（同赛事、同来源、一级赛项、证件规范化集合匹配，ENTRY需完整成员集合，PARTICIPANT需对应参赛人），记录关联与理由后进入国审。尚无国赛作品显示待独立报名。本切片不新增前台国赛报名入口。

### 评奖

- 规则适用赛事、阶段、ENTRY/PARTICIPANT、一级赛项，可选专业/组别，包含奖项名、闭区间[min,max]、排序、enabled与revision。只评评分对象奖，不派生教师/学校奖。区间在综合分范围内，不允许同一可重叠适用域的启用规则交叠；端点相同也算交叠，通配与具体范围重叠同样拒绝，不能靠优先级掩盖冲突。
- 只读取有效确认finalVersion；预览返回命中、未命中、冲突、失效成绩及对应规则。多人同分均获同奖，不设名额、排名或比例截断。预览token绑定赛事、阶段、规则/最终成绩版本和完整候选快照，30分钟过期。
- 确认时阶段锁、重验hash与当前版本；冲突或失效输入拒绝。一个事务生成CONFIRMED批次、批次专属awards/award_grants及规则/分数快照，不复用其它批次的可变award行。
- 对同一阶段/候选已有有效奖项的再次确认须明确替代原批次，不允许两个批次同时成为同对象同阶段有效结果；替代原子标旧批次STALE并建立supersedesBatchId关系。子集替代若与原批次候选不一致则拒绝，须按原批次完整候选重做，避免误停未选中对象的奖项。
- 确认幂等键存储payloadHash与结果；相同键同体返回原batchId，不同体409。撤销带原因/expectedVersion，仅改变所属批次及其专属授奖有效状态；旧批次再撤销不能影响替代批次。原始快照不可覆盖。
- 不生成证书、不公开成绩；后续查询只能消费有效确认结果，STALE/REVOKED不得作为可发布数据。

### 作品清单导出（2026-10-17 追加）

用户要求导出作品清单供后续奖项导入。本切片提供下载与稳定匹配字段，奖项导入执行另行实现。

- `POST /api-backend/cqt/review/exportEntries`，独立权限 `cqt:entry-review:export`，操作日志仅记录筛选参数；Cookie/CSRF 沿用后台规则。
- JSON 请求：`competitionId`、`phaseId` 必填正整数；阶段必须属于赛事且为 PROVINCIAL / NATIONAL。可选 `keyword`（最多200字符）、`source`（zhongxi/qudao/houtai）、`status`（初审状态0/1/2/3），均与作品初审列表相同语义；不受列表分页限制。
- 只导出未删除作品及选定阶段相容的作品（省审排除 NATIONAL-only，国审排除 PROVINCIAL-only）。中戏每作品一行，渠道/后台每有效参赛人一行；缺少有效参赛人时仍保留一条问题行。左关联预期类型的 ACTIVE 评分对象，缺失时对象编号为空、状态标“未准备”，不自动创建对象、不悄悄丢掉作品。来源与 scoring_scope 不一致必须标明问题，不允许把其旧对象冒充正确对象。
- 响应直接为 XLSX 二进制，Content-Type 为标准 Excel 类型，Content-Disposition attachment，固定安全文件名 `cqt-entries-<competitionId>-<phaseId>.xlsx`；不包 JSON，失败仍为标准错误包络。`Cache-Control: no-store`。空数据返回带表头的工作簿；超过10000行返回400，提示缩小范围，禁止静默截断。
- 工作表“作品清单”固定列顺序：赛事编号、赛事、阶段编号、阶段代码、阶段、作品唯一ID、报名号、作品名称、数据来源、评分对象编号、评分对象类型、参赛人编号、参赛人、赛区、赛项、专业、组别、初审状态、对象状态、成绩状态、最终成绩、成绩版本、奖项。ID及报名号按 Excel 文本单元格输出；ENTRY 的参赛人编号/姓名留空；非 VALID 成绩及缺失成绩的最终成绩留空，保留状态和已有版本，不用0冒充缺分。“奖项”列为空，留给后续填写。
