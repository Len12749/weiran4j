## 2. Gradle 模块

```
weiran4j/
├── build-logic/                 # 约定插件（质量门禁唯一来源）
├── weiran-dependencies/         # BOM：import spring-boot-dependencies + mybatis-plus-bom，钉 jjwt/springdoc/testcontainers 版本
├── weiran-framework/            # 框架层（D-016 并入原 weiran-common）：
│                                #   纯 Java 契约包 error / page / response / status / text / tree（ErrorCode / BizException / CommonErrors / PageQuery / PageResult / ApiResponse）
│                                #   + Spring 基础设施（替代 wuli3）：统一响应、全局异常、认证拦截、权限注解、操作日志切面、MyBatis-Plus 配置
├── weiran-system/               # 后台基座（DDD 五层，D-011 由 system + platform 合并而来）
│   └── weiran-system-{api,domain,application,infrastructure,adapter}
│       ├── com.weiran.system.*    # 身份与权限：auth / user / role / menu / department / login-log
│       └── com.weiran.platform.*  # 平台能力：dict / config / operation-log
└── weiran-app/                  # 启动模块：只聚合依赖 + application.yml + 集成测试
```

依赖方向：`adapter → application → domain`，`infrastructure → domain`，`application → api`。
所有层都依赖 `weiran-framework`，但它的 Spring / MyBatis-Plus 依赖是 `implementation`、不向下游传递（D-016）：
**domain 与 api 只能用它的纯 Java 契约包**（编译期本来也看不到框架类型）；application / infrastructure / adapter 用到哪个框架库自己声明。

各层职责：

| 层 | 放什么 | 禁止 |
| --- | --- | --- |
| api | 对外 DTO（record）、应用服务接口、命令对象 | Spring、MyBatis |
| domain | 聚合/实体/值对象、领域规则、仓储端口（接口） | 任何框架 |
| application | 实现 api 的服务接口，编排用例，`@Transactional` 边界 | `*DO`、Mapper |
| infrastructure | `*DO`、Mapper、仓储实现、JWT、BCrypt、Flyway 脚本 | Controller |
| adapter | `@RestController`、请求 DTO 与校验、`@RequiresPermission`、`@OperationLog` | 直接调 Mapper |

每个模块用 `@AutoConfiguration` + `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`
自我登记；Mapper 用 `@MapperScan` 写在该模块 infrastructure 的自动配置里。`weiran-app` 不写 `@ComponentScan`。

### 2.2 下游扩展入口（D-012）

以 git fork 跟随本仓的下游项目，只在下面这些位置落改动，不修改任何上游文件，同步上游时就不会冲突。
**「下游怎么做」一列里的文件与目录归下游独占，上游永不创建**（`business-modules.md` 例外：上游建好表头，下游只追加行）。

| 扩展什么 | 下游怎么做 | 上游的接入点 |
| --- | --- | --- |
| 业务模块 | 建 `weiran4j/weiran-<mod>/weiran-<mod>-{api,domain,application,infrastructure,adapter}/` 五个目录 | `settings.gradle.kts` 自动发现，写入 `gradle.extra["weiran.businessModules"]`；BOM 坐标与 `weiran-app` 的依赖、覆盖率聚合据此生成。**含任一层却五层不齐时构建失败** |
| 号段登记 | 在 `business-modules.md` 追加一行 | 见 §2.1 |
| 业务默认配置 | 在某个业务模块的 `src/main/resources/` 放 `application-biz.yml`（全应用只能有一份） | `application.yml` 的 `spring.config.import: optional:classpath:application-biz.yml`。它覆盖 `application.yml` 的同名键，但低于 profile 文件（如 `application-local.yml`）与环境变量。**密钥不放这里**，仍走环境变量（CP-9） |

| 菜单图标 | `web/src/biz/icons*.ts` 具名导出 `export const icons: Record<string, LucideIcon>` | `web/src/utils/icons.tsx` 用 `import.meta.glob` 合并；与基座同名时以基座为准 |

#### CQT 学校作品批量导入（change `cqt-school-batch-import`）

前台接口均使用 `/api-web/**` 与 `{code:200,message,data}`，由登录学校账号身份限定数据范围；客户端 `userid` 不可信且忽略。

| 路由 | 方法 | 请求 | 返回 |
|---|---|---|---|
| `/api-web/auth/getexinfo` | GET | 无 | 模板 URL；模板表包含报名字段至“渠道标识”，不含省赛/国赛奖项列 |
| `/api-web/cqt-import/template.xlsx` | GET | 无 | 空白 XLSX 二进制模板 |
| `/api-web/competition/checksignup` | GET | 可选 `competitionid` | `data:boolean`，是否存在待处理导入 |
| `/api-web/competcategory/schoolproductlists` | GET | 可选 `competitionid` | 当前学校作品数组 |
| `/api-web/dramacompetition/uploadAttachmentZiposs` | POST | `{oss_zip_url}` | `{session_id}` |
| `/api-web/dramacompetition/uploadexceloss` | POST | `{session_id,oss_excel_url}` | `{excel_id}` |
| `/api-web/dramacompetition/confirmImportoss` | POST | `{type,competitionid,session_id,excel_id,userid,zip_name,excel_name}` | `{task_id,job_id,competitionid,message}`；job_id 为同一任务ID的兼容别名，忽略 `userid` |
| `/api-web/dramacompetition/importProgress/{taskId}` | GET | 不透明字符串任务ID | 当前学校任务状态与进度，见下 |
| `/api-web/dramacompetition/importResult/{taskId}` | GET | 不透明字符串任务ID | 当前学校逐行结果与汇总，见下 |
| `/api-web/competition/getTaskResult` | POST | `{competitionid}` | `{data:[task...]}`；仅当前学校 |
| `/api-web/competition/getTaskDetail` | GET | `Competitionid`,`id` | 任务汇总及 `results[]`；仅当前学校 |

Excel 根据“报名表”第二行表头名称映射。个人每行一件作品；团体按人数消费连续成员行，并校验人数、赛项、专业与作品名称一致。ZIP 内附件按安全规范化文件名匹配后抽取为学校账号独立存储对象，并关联对应作品；作品附件类型增加 `FILE`（保留既有 `ZIP`、`LINK`）。任务详情按每条非空 Excel 源行返回结果，同一团体成员共享组处理状态与作品 ID。上传会话从创建或最近一次文件登记起两小时失效。省赛、国赛奖项列不读取、不校验、不导入；省赛/国赛评价在作品创建后的业务阶段处理。

进度/结果查询不要求客户端提供赛事ID，服务端按登录学校账号和 taskId 双重定位；其它学校的任务与不存在的任务统一返回不存在，学生账号无权查询。继续复用 `cqt_school_import_tasks/rows`，不创建第二套任务表。

任务表通过追加迁移 `V202610170200__cqt_import_task_error.sql` 增加可空 `error_message`（varchar(2000)），保存解析失败、会话过期或重试耗尽等任务级错误，查询时优先作为 message 返回。解析前失败保留真实0行，不伪造错误源行；空模板以FAILED结束并提示“报名表没有可导入的作品行”。已有源行仍保留逐行错误和成功结果。业务校验失败标记对应源行失败，作品写入或结果登记的基础设施异常保留待处理状态，供租约恢复通过作品指纹幂等重放；重试耗尽已有成功行为PARTIAL，否则FAILED。

- 进度字段：`task_id/job_id,competitionid,state,status,finished,progress,message,total_rows,processed_rows,success_count,failed_count`。state 为 UPLOADING/QUEUED/PROCESSING/COMPLETED/PARTIAL/FAILED；status 兼容旧数值：上传/排队0、处理中1、完成或部分成功2、失败3。finished 仅后三种终态为true。progress 取真实处理行数比例，非终态最高99，终态100；未知总行数时0，不能用模拟定时器虚增。
- 结果字段：上述状态、计数及 `results[]/success_rows[]/failed_rows[]/completed_at`；results 是源行数组，行status为待处理0、成功1、失败2（不能把待处理当失败）。completed_at 仅终态使用任务updatedAt，未结束为null。成功/失败数组仅包含对应终态行；不臆造附件匹配/缺失统计。
- 任务列表与原任务详情同步提供 state/finished/progress 和 processed_rows 等计数，PARTIAL 显示部分成功，不能当作未完成或全部失败。详情结果保留原有 row_data/col_* 兼容字段。
- 前台提交成功记录 task_id 并立即查询进度；单次请求完成后再安排下一次，避免重叠与重复结果弹窗。页面隐藏/卸载/切换任务时停止定时器并忽略过期响应；回到页面可恢复当前任务轮询，历史记录可重新打开查看。终态成功、部分成功、失败均停止轮询并展示真实统计及逐行错误；网络失败提供手动重试，业务错误不能让Promise永远pending。

下游依赖清单写法（applied 脚本里没有 `api(...)` 访问器，配置名写成字符串）：

```kotlin
// weiran4j/weiran-dependencies/biz-dependencies.gradle.kts —— 下游独占，上游永不创建
dependencies {
    constraints {
        add("api", "com.aliyun:dysmsapi20170525:<版本>")
    }
    add("api", platform("<第三方 BOM 坐标>:<版本>")) // 需要时
}

// 业务库把框架依赖传递拉高、且确认可接受时才写；理由必填，为空即失败
extra["weiran.bizVersionDriftAllowlist"] = mapOf(
    "com.squareup.okhttp3:okhttp" to "dysmsapi 需要 4.12，已验证与框架兼容",
)
```

「框架已管理」= 上游 `weiran-dependencies` 里 import 的 Spring Boot / MyBatis-Plus BOM 与上游 constraints 能给出版本的模块。
Gradle 对 `platform` 的版本冲突取高，下游钉高等于悄悄升级框架、钉低会被静默忽略，所以两种都直接拦下。

业务模块的 `application` / `infrastructure` / `adapter` 计入 `weiran-app` 的跨模块覆盖率聚合，门槛（行覆盖 70%）对下游代码同样生效。

## 3. weiran-framework 提供的扩展点

| 类型 | 名称 | 说明 |
| --- | --- | --- |
| 注解 | `@PublicApi` | 标在 Controller 类或方法上：无需登录 |
| 注解 | `@RequiresPermission(value = {"system:user:list"}, logical = ANY)` | 需要任一权限码；超管角色 `super_admin` 直接放行 |
| 注解 | `@OperationLog(module = "用户管理", description = "新增用户")` | 切面记录操作日志（请求体脱敏 `password` 等字段、截断 4096） |
| 注解 | `@SkipApiResponse` | 标在 Controller 类或方法上（也可作元注解）：返回值原样写出，不包 `{code, message, data}`。**只用于 `/api/**` 之外的前缀**（如下游的 `/api-web/**`），`/api/**` 一律走统一包络 |
| SPI | `TokenAuthenticator` | `Optional<LoginUser> authenticate(String token)`；由 system 模块实现（`DispatchingTokenAuthenticator`：按 `iss` 选校验器 → 认身份并判吊销 → 取权限，D-014） |
| 过滤器 | `RequestIdFilter` | 最高优先级、作用于全部路径：请求号（入站 `X-Request-Id` 合法即沿用，否则生成 32 位十六进制）写入 MDC `requestId` 与响应头；请求结束时对 `/api/**` 打访问日志（logger `com.weiran.access`：`{method} {path} {status} {ms}ms user={id\|-} ip={ip}`，不含请求体与查询值；`/api/health` 为 DEBUG） |
| 记录 | `ErrorResponse(int code, String message, Object data, String requestId)` | 失败响应体，只由全局异常处理器产生；成功体仍是 `weiran-framework` 纯 Java 契约包里的 `ApiResponse` |
| 工具 | `MdcTaskDecorator` | `TaskDecorator`：把提交方的 MDC（含请求号）带进线程池，执行完恢复；操作日志线程池在用 |
| 工具 | `AuthCookies` | 浏览器认证 Cookie 的唯一定义处：名称常量、`issue(token, ttl, userId)` / `clear()` 生成 `ResponseCookie`、`csrfUserId(value)`；配置 `weiran.auth.cookie.secure`（默认 `true`，环境变量 `WEIRAN_COOKIE_SECURE`） |
| SPI | `OperationLogRecorder` | `void record(OperationLogEvent event)`；由 platform 模块实现（异步落库，失败只记日志不影响业务） |
| SPI | `AuditorProvider` | 给 MyBatis-Plus 自动填充 `created_by/updated_by`；默认从 `CurrentUser` 取 |
| 工具 | `CurrentUser` | `static Optional<LoginUser> get()` / `LoginUser require()`（未登录抛 401） |
| 记录 | `LoginUser(long id, String username, String nickname, Set<String> roles, Set<String> permissions, String idp)` | `isSuperAdmin()` = roles 含 `super_admin`；`idp` 为本次会话的外部身份提供方 id（外部登录签发的令牌带 `idp` claim），密码登录为 null；保留不带 `idp` 的 5 参构造器 |

认证流程：`AuthInterceptor`（HandlerInterceptor，只拦 `/api/**`）→ 取令牌（`Authorization: Bearer <token>` 优先，
其次 `weiran_token` Cookie）→ `TokenAuthenticator` → 没有 `@PublicApi` 且未登录返回 401 →
以 Cookie 认证的写请求做 CSRF 双提交校验（见 §4，不通过返回 403 / `40302`）→ 检查 `@RequiresPermission`，不满足返回 403 →
全部通过后才放入 `CurrentUser`（ThreadLocal，`afterCompletion` 清理）。拦截器里抛 `BizException`，由全局异常处理器统一输出。

令牌吊销：用户表 `token_version` 列。JWT 里带 `ver` claim；改密码 / 禁用 / 管理员重置密码时 `token_version + 1`，
旧令牌立即失效。**令牌版本与账号状态每次请求按主键查库，不经过缓存**，所以多实例下吊销同样立即生效；
用户名、昵称、角色、权限码组成的快照走进程内 Caffeine 缓存（30s，本进程内改权限时主动失效），
多实例下角色 / 权限变更最多有 30s 的生效延迟（`openspec/state/bizs/artifact.md#02`）。

## 4. HTTP 约定

- 前缀统一 `/api`；JSON 字段 camelCase；时间格式 `yyyy-MM-dd HH:mm:ss`（`Asia/Shanghai`）；ID 为数字（bigint 自增）。
- 统一响应（HTTP 状态码与 `code` 一致或为 200）：

```jsonc
{ "code": 0, "message": "ok", "data": { ... } }          // 成功，code 恒为数字 0；没有 requestId 键
{ "code": 40100, "message": "登录已失效，请重新登录", "data": null, "requestId": "3f1c…" }  // 失败
```

- **请求号**：所有响应带 `X-Request-Id` 头；**失败**响应体额外带 `requestId`，与响应头相同（成功体不带）。
  请求可以自带 `X-Request-Id`（`[A-Za-z0-9_-]{1,64}` 时沿用，便于和 Nginx / 网关日志串联），否则服务端生成 32 位小写十六进制。
  前端在错误提示末尾显示前 8 位，用户报障时据此在日志里检索（见 [`02-部署.md`](02-部署.md)「日志与排障」）。

- 错误码：五位数字，前三位 = HTTP 状态码，后两位序号按 §2.1 分段（宪法 CP-14）。通用码在 `CommonErrors`：

| code | HTTP | 含义 |
| --- | --- | --- |
| 40000 | 400 | 参数校验失败（message 形如 `username: 不能为空`） |
| 40100 | 401 | 未登录 / 令牌无效 / 已失效 |
| 40101 | 401 | 用户名或密码错误 |
| 40300 | 403 | 无权限 |
| 40301 | 403 | 账号已禁用 |
| 40302 | 403 | CSRF 校验失败（Cookie 认证的写请求缺少或带错 `X-CSRF-Token`）；前端按普通错误提示，不清会话 |
| 40102 | 401 | 外部身份校验失败（票据 / 授权码无效、state 不符、id_token 验签失败、流程过期）；只出现在外部登录回调的 `ssoError` 里 |
| 40303 | 403 | 账号未开通（外部身份未绑定且不允许自动开通，或与未绑定的本地同名用户冲突，D-015） |
| 40304 | 403 | 密码登录已关闭（`weiran.auth.password-login.enabled=false`，内置超管除外） |
| 40400 | 404 | 资源不存在 |
| 40900 | 409 | 唯一键冲突（如用户名、角色编码、字典编码已存在） |
| 40901 | 409 | 业务状态冲突（如删除有子节点的部门/菜单、删除内置数据） |
| 50000 | 500 | 服务器内部错误（message 不暴露堆栈） |

- **部署：前端页面与 `/api` 必须同源**（开发走 vite 代理，线上走反向代理），后端不提供 CORS。
  `VITE_API_BASE_URL` 只能是路径前缀，写成 `http(s)://` 绝对地址时前端构建直接失败。反向代理必须透传 `Cookie`、`Set-Cookie` 与 `X-CSRF-Token`。
- **令牌携带**：受保护接口接受 `Authorization: Bearer <token>`（非浏览器调用方）或 `weiran_token` Cookie（浏览器），两者都有时以 Bearer 为准。
  浏览器登录后服务端下发两个 Cookie，`Secure` 由 `weiran.auth.cookie.secure` 决定：

  | Cookie | 属性 | 值 | 用途 |
  | --- | --- | --- | --- |
  | `weiran_token` | `HttpOnly; SameSite=Strict; Path=/api; Max-Age=<令牌有效期>` | JWT | 认证；页面脚本读不到 |
  | `weiran_csrf` | `SameSite=Strict; Path=/; Max-Age=<令牌有效期>` | `<userId>.<32 字节随机数 base64url>` | 前端据此判断登录态与当前用户 id，并回填到请求头；不是凭据 |

- **CSRF 双提交**：以 Cookie 认证的、非 `@PublicApi` 的 `POST` / `PUT` / `PATCH` / `DELETE` 请求必须带 `X-CSRF-Token` 头，
  值与 `weiran_csrf` Cookie 逐字相等，且其 userId 前缀等于当前用户；否则 403 / `40302`，业务代码不执行。
  `GET` / `HEAD` / `OPTIONS`、Bearer 认证的请求、公开接口不查。
- 分页：请求参数 `page`（从 1 开始，默认 1）、`pageSize`（默认 20，最大 200）；响应 `data` = `{ list, total, page, pageSize }`。
- 状态字段统一字符串枚举：`status: "enabled" | "disabled"`。
- 库中 tinyint 标志位（`visible`、`keepAlive`、`isExternal`、`isBuiltin`、`success`）在 JSON 中一律为 **boolean**。
- `PUT /api/roles/{id}/menus` 的 `menuIds` 可包含 directory 类型节点（前端勾选子节点会连带勾选祖先）。

### 6.1 认证 `/api/auth`（system）

| 方法 | 路径 | 权限 | 请求 | 响应 data |
| --- | --- | --- | --- | --- |
| POST | /login | 🔓 | `{username, password}`；可选请求头 `X-Auth-Mode: token` | 默认（浏览器）：`{tokenType:"Bearer", expiresIn(秒), userId}`，令牌只通过 `Set-Cookie` 下发 `weiran_token` 与 `weiran_csrf`（见 §4），响应体**不含** `accessToken`；带 `X-Auth-Mode: token`（脚本 / 非浏览器）：`{accessToken, tokenType:"Bearer", expiresIn, userId}`，**不写** Cookie，之后用 Bearer 头调用 |

**外部身份登录（D-015）**：提供方用 `weiran.auth.providers.<id>.*` 配置（环境变量 `WEIRAN_AUTH_PROVIDERS_<ID>_*`，见 `02-部署.md`），类型 `oidc`（授权码 + PKCE + state + nonce，id_token 经 JWKS 验签）或 `cas`（3.0 `/p3/serviceValidate`）。
外部身份只按 `(provider, external_id)` 映射本地用户；未绑定时按提供方 `auto-provision` 决定拒绝（40303）或自动开通（无本地密码、默认角色），**不自动关联同名本地用户**。外部登录签发的仍是本地 JWT（多一个 `idp` claim）。
`weiran.auth.password-login.enabled=false` 时只有内置超管能用密码登录，其余 40304。对外地址 `weiran.auth.public-base-url`（`WEIRAN_PUBLIC_BASE_URL`）用于拼回调与登出回跳，不从请求头推断。

登录规则：用户名不存在与密码错误**同一个错误码 40101**（防枚举）；禁用账号 40301；成功/失败都写 `sys_login_log`；
成功后更新 last_login_at/ip。JWT：HS256，claims `sub`=userId、`username`、`ver`、`iss`、`aud`，有效期默认 12h，密钥 ≥ 32 字节，缺失则启动失败。
`iss` 缺失、不认识或 `aud` 不含本系统的令牌一律 40100。配置键 `weiran.auth.jwt.secret|ttl|issuer|audience`（环境变量
`WEIRAN_JWT_SECRET|TTL|ISSUER|AUDIENCE`，`issuer` / `audience` 默认 `weiran4j`）；2026-10-05 起由 `weiran.system.jwt.*` 改名而来（D-014），
改名后此前签发的令牌（没有 `iss`）全部失效，需要重新登录。
基座对外另有只校验凭据、不签发令牌的 `AuthService.authenticate(username, password, client)`：规则与登录相同（同一 40101、失败写日志、禁用 40301），
成功时不写成功日志——登录接口复用它，供将来的外部身份登录使用。

`MenuNode = {id, parentId, title, type, path, component, icon, permission, sort, visible, keepAlive, isExternal, status, children: MenuNode[]}`

偏好字段的定义（44 个，含默认值）以前端 `web/src/hooks/usePreferences.tsx` 为唯一事实源；后端只存不校验字段含义。
Flyway：`V202609270001__system_user_preferences.sql`（system 模块）给 `sys_user` 追加 `preferences`、`favorite_menus` 两列。
`sys_user.updated_at` 只反映资料 / 状态 / 角色 / 密码等真实变更：登录、偏好与收藏的保存**不刷新**它。MySQL JSON 列会重排对象键顺序，前端不要依赖偏好对象的键序。

## 常青藤后台评审、评分与评奖

用户2026-10-17确认实施，change `cqt-review-scoring-awards`。本节为实施契约，评分及评奖接口均为后台；前台查分与证书后置。

## Data Flow

### 来源与对象

1. 新普通/团体/学校导入作品source_database取当前账号来源；zhongxi派生scoring_scope=ENTRY，qudao/houtai派生PARTICIPANT。中戏每作品一个目标，其余每有效参赛人一个目标；报名和导入仍在原作品组事务内完成。
2. 历史作品以已存source_database为权威，不由成员、学校或渠道名称反推。准备预览按来源核对scoring_scope与目标集合；只有无任务、评分、汇总和奖项引用时可修正，保留旧目标为非ACTIVE并幂等建立正确集合。有引用的冲突明确阻断，不自动迁移评分。
3. 历史正确目标及ID保持；多次准备不得新增重复目标。同作品不允许ENTRY和PARTICIPANT同时作为有效评分集合。团体人员级对象分别显示参赛人，所有写入以targetId而非entryId定位。

### 初审与阶段

- INITIAL为管理员对作品的定性初审，不分配多人评委、不录数字分；通过/驳回、原因、操作者、版本和历史留档。驳回须原因；通过可附意见。
- 每赛事有INITIAL/PROVINCIAL/NATIONAL唯一阶段。省国审配置总分上下限、最低评委数、可空晋级线；数字至多两位，最低人数≥1。阶段状态DRAFT→OPEN→CLOSED→FROZEN；首次OPEN前规则与目标准备完整。
- 初审通过的有效作品对应目标进入省审候选，NATIONAL-only作品不进入省审。阶段关闭立即拒绝评分草稿和提交；FROZEN表示已确认汇总。
- 管理员在未产生下游评分前可带原因重审；已有省国审评分时不可直接撤回初审，需先显式失效相应阶段/下游结果，保留历史。

### 规则与范围

- 评分规则/维度保存不可变revision；维度按阶段+一级赛项管理名称、说明、记录分区间、排序。OPEN后不得原地改规则；需关闭并重开新revision。新的revision不会沿用旧草稿或把旧提交冒充新评分，页面显示待重新评分。
- 评委范围包含userId、competitionId、phaseCode、省/国阶段、一级赛项、可选专业/赛区、enabled。专业/赛区为空为不限；所有外键与父子关系及赛事一致性由服务端核验。
- 管理员业务权限默认覆盖全部赛事，不新造全局赛事/来源ACL；评委只见本人有效assignment，且每次读取/写入核验用户启用、scope匹配、作品/参赛人/目标有效及当前阶段。即使知道他人ID也不可读写。
- 停用范围使匹配任务不可提交，已有提交只保留历史并使相关有效汇总/奖项STALE；范围不能被简单删除来掩盖影响。操作先预览影响并带原因确认。基座用户禁用没有CQT事件回调，本切片不增加事件/worker：每次业务读取、预览和确认通过UserService重新取用户状态及updatedAt，发现禁用或快照变化后惰性使相关结果STALE并拒绝旧预览。与基座禁用并发的请求以本次校验快照为准，下一业务读取重新核验，不承诺跨模块瞬时推送失效。

### 分配与评分

- 手工分配和自动分配都先预览，返回target、reviewer、已有任务、越界/缺人原因、工作量与previewToken。自动分配在合法scope候选中按当前有效任务数、userId稳定排序，补齐每对象指定人数，不重复分配已有有效评委。
- 确认时重验作品、阶段、规则、scope、用户状态和候选版本。存在未覆盖对象须调整范围或显式从候选中移除后重新预览，不默认静默跳过。单次候选≤500目标，总新任务≤5000，超限要求缩小筛选，事务不承接无限全表任务。
- 同阶段同对象同评委唯一；CANCELLED任务可恢复且沿用assignmentId，恢复重验范围。取消已提交任务必须额外管理权限、原因及影响预览，旧评分留档，不再计入有效评分，关联结果STALE。
- 评分状态EMPTY/DRAFT/SUBMITTED；草稿可不完整，提交要求所有启用维度的记录分和评语、独立综合分齐全且在范围内，维度不计算权重、不相加替代综合分。评语trim后非空且≤2000字，分数字段最多两位。
- 请求带expectedVersion，评分写入CAS；当前用户决定reviewerId，不接受客户端替换。开放且未冻结时可修订，旧记录保留revision；相同内容的幂等重试不追加重复修订。未提交草稿不得进入平均分。

### 汇总、复核与晋级

- 管理员关闭阶段后预览汇总。以有效且提交、对应当前规则revision的不同评委综合分计算普通平均，HALF_UP两位。至少达到minimumReviewers才有成绩；无需所有分配评委均提交，预览明确列出待评、缺评和未达最低人数。
- 确认携带输入版本hash，事务锁阶段行，再重验当前评分/assignment/scope/目标/规则版本；所有会改变输入的操作也锁同一阶段行并递增inputVersion。任一漂移409要求重新预览，不基于陈旧快照确认。
- 汇总为本阶段全部当前候选生成确认快照；可确认达标子集，未达最低人数或失效对象仅生成缺评/失效快照并将旧成绩标STALE，不产生有效新final。预览须明确完整达标与跳过清单，管理员显式接受缺评后才能确认并令阶段FROZEN；没有任何达标对象时拒绝确认。用户要补评时需重开再评分汇总。有效最终分与计算快照记录原评分revision和规则revision。
- 成绩管理员仅在FROZEN阶段可带理由更正有效最终分，不修改评委原始分；更正记录前后值与操作者，生成新finalVersion，使相关已确认奖项批次STALE并保留原奖项历史。需重新预览评奖才能形成新有效奖项。
- 重开阶段必须原因与影响预览；使该阶段及依赖它的晋级/下游已生成结果失效待复核，不删除历史。FROZEN阶段不接受直接评分；重开后显式处理旧final/award状态。
- 晋级状态ELIGIBLE/ADVANCED/ELIMINATED/LOCKED，独立于计算状态，重算不得把人工决定悄悄重置。阈值仅产生建议名单，管理员确认后才晋级；人工决定必须原因。前置最终成绩失效时晋级标待复核，不继续推进。
- SHARED赛事确认晋级后将同一target纳入国审；SEPARATE只生成资格，绝不复制作品或绕过独立报名。已有合法NATIONAL/BOTH作品可由管理员关联资格（同赛事、同来源、一级赛项、证件规范化集合匹配，ENTRY需完整成员集合，PARTICIPANT需对应参赛人），记录关联与理由后进入国审。尚无国赛作品显示待独立报名。本切片不新增前台国赛报名入口。

### 评奖

- 规则适用赛事、阶段、ENTRY/PARTICIPANT、一级赛项，可选专业/组别，包含奖项名、闭区间[min,max]、排序、enabled与revision。只评评分对象奖，不派生教师/学校奖。区间在综合分范围内，不允许同一可重叠适用域的启用规则交叠；端点相同也算交叠，通配与具体范围重叠同样拒绝，不能靠优先级掩盖冲突。
- 只读取有效确认finalVersion；预览返回命中、未命中、冲突、失效成绩及对应规则。多人同分均获同奖，不设名额、排名或比例截断。预览token绑定赛事、阶段、规则/最终成绩版本和完整候选快照，30分钟过期。
- 确认时阶段锁、重验hash与当前版本；冲突或失效输入拒绝。一个事务生成CONFIRMED批次、批次专属awards/award_grants及规则/分数快照，不复用其它批次的可变award行。
- 对同一阶段/候选已有有效奖项的再次确认须明确替代原批次，不允许两个批次同时成为同对象同阶段有效结果；替代原子标旧批次STALE并建立supersedesBatchId关系。子集替代若与原批次候选不一致则拒绝，须按原批次完整候选重做，避免误停未选中对象的奖项。
- 确认幂等键存储payloadHash与结果；相同键同体返回原batchId，不同体409。撤销带原因/expectedVersion，仅改变所属批次及其专属授奖有效状态；旧批次再撤销不能影响替代批次。原始快照不可覆盖。
- 不生成证书、不公开成绩；后续查询只能消费有效确认结果，STALE/REVOKED不得作为可发布数据。
