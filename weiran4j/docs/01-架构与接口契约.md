> 本文是 2026-09-26 重写的**唯一契约来源**。前后端都按本文实现；实现与本文不符时，先改本文再改代码。
>
> 重写的三条前提（D-008）：
> 1. **不再兼容 PHP weiran-v1**：不读写 `pam_*` 表，不保留历史密码算法，不保留 `/api/v1` 前缀。

> 3. **能力对标 mono4ts 的「标准后台底座」**：登录/JWT、用户、角色、菜单（动态路由 + 按钮权限）、部门、

## 2. Gradle 模块

```
weiran4j/
├── build-logic/                 # 约定插件（质量门禁唯一来源）
├── weiran-dependencies/         # BOM：import spring-boot-dependencies + mybatis-plus-bom，钉 jjwt/springdoc/testcontainers 版本
├── weiran-framework/            # 框架层（D-016 并入原 weiran-common）：
│                                #   纯 Java 契约包 error / page / response / status / text / tree（ErrorCode / BizException / CommonErrors / PageQuery / PageResult / ApiResponse）
│                                #   + Spring 基础设施（替代 wuli3）：统一响应、全局异常、认证拦截、权限注解、操作日志切面、MyBatis-Plus 配置
├── weiran-system/               # 后台基座（DDD 五层，D-011 由 system + platform 合并而来）
│   └── weiran-system-{api,domain,application,infrastructure,adapter}
│       ├── com.weiran.system.*    # 身份与权限：auth / user / role / menu / department / login-log
│       └── com.weiran.platform.*  # 平台能力：dict / config / operation-log
└── weiran-app/                  # 启动模块：只聚合依赖 + application.yml + 集成测试
```

依赖方向：`adapter → application → domain`，`infrastructure → domain`，`application → api`。
所有层都依赖 `weiran-framework`，但它的 Spring / MyBatis-Plus 依赖是 `implementation`、不向下游传递（D-016）：
**domain 与 api 只能用它的纯 Java 契约包**（编译期本来也看不到框架类型）；application / infrastructure / adapter 用到哪个框架库自己声明。

各层职责：

| 层 | 放什么 | 禁止 |
| --- | --- | --- |
| api | 对外 DTO（record）、应用服务接口、命令对象 | Spring、MyBatis |
| domain | 聚合/实体/值对象、领域规则、仓储端口（接口） | 任何框架 |
| application | 实现 api 的服务接口，编排用例，`@Transactional` 边界 | `*DO`、Mapper |
| infrastructure | `*DO`、Mapper、仓储实现、JWT、BCrypt、Flyway 脚本 | Controller |
| adapter | `@RestController`、请求 DTO 与校验、`@RequiresPermission`、`@OperationLog` | 直接调 Mapper |

每个模块用 `@AutoConfiguration` + `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`
自我登记；Mapper 用 `@MapperScan` 写在该模块 infrastructure 的自动配置里。`weiran-app` 不写 `@ComponentScan`。

### 2.2 下游扩展入口（D-012）

以 git fork 跟随本仓的下游项目，只在下面这些位置落改动，不修改任何上游文件，同步上游时就不会冲突。
**「下游怎么做」一列里的文件与目录归下游独占，上游永不创建**（`business-modules.md` 例外：上游建好表头，下游只追加行）。

| 扩展什么 | 下游怎么做 | 上游的接入点 |
| --- | --- | --- |
| 业务模块 | 建 `weiran4j/weiran-<mod>/weiran-<mod>-{api,domain,application,infrastructure,adapter}/` 五个目录 | `settings.gradle.kts` 自动发现，写入 `gradle.extra["weiran.businessModules"]`；BOM 坐标与 `weiran-app` 的依赖、覆盖率聚合据此生成。**含任一层却五层不齐时构建失败** |
| 号段登记 | 在 `business-modules.md` 追加一行 | 见 §2.1 |
| 业务默认配置 | 在某个业务模块的 `src/main/resources/` 放 `application-biz.yml`（全应用只能有一份） | `application.yml` 的 `spring.config.import: optional:classpath:application-biz.yml`。它覆盖 `application.yml` 的同名键，但低于 profile 文件（如 `application-local.yml`）与环境变量。**密钥不放这里**，仍走环境变量（CP-9） |
| 第三方依赖版本 | `weiran4j/weiran-dependencies/biz-dependencies.gradle.kts` 登记版本约束、按需 import 第三方 BOM（写法见下）；业务模块照常不写版本 | `weiran-dependencies` 在该文件存在时 apply（D-013）。`weiran-app` 的 `check` 含 `verifyFrameworkVersions`：**下游清单不得约束框架已管理的依赖**（不论高低）；框架依赖被传递拉离框架版本时失败，确认可接受的写进下游白名单并写理由 |
| Flyway 脚本 | 放 `db/migration/<mod>/`（CP-15） | `spring.flyway.out-of-order: true`：上下游脚本时间戳交错时，后到的低版本脚本会被补执行而不是让启动失败。因此**脚本之间不得依赖版本号顺序之外的执行次序** |
| 非 `/api/**` 接口的响应格式 | Controller 类或方法标 `@SkipApiResponse`（见 §3） | `ApiResponseBodyAdvice` 不包 `{code:0}`。异常仍由 `GlobalExceptionHandler`（`LOWEST_PRECEDENCE`）处理，下游可用更高优先级的 `@RestControllerAdvice` 覆盖 |
| 菜单图标 | `web/src/biz/icons*.ts` 具名导出 `export const icons: Record<string, LucideIcon>` | `web/src/utils/icons.tsx` 用 `import.meta.glob` 合并；与基座同名时以基座为准 |
| 页面 | `web/src/pages/<mod>/**` | `page-registry.ts` 的 glob 自动收集 |
| AI 协作规范 | 仓库根 `AGENTS.biz.md` | `AGENTS.md` 声明存在即必读 |
| 公共组件登记 | `openspec/rules/advisory/components.biz.md`，并在 `AGENTS.biz.md` 的规则索引表登记它 | `components-registry` 守卫把它与 `components.md` 一并当作登记来源；`rules-index` 守卫把 `AGENTS.biz.md` 与 `AGENTS.md` 一并当作索引来源 |
| 现状文档索引 | `openspec/state/bizs/README.biz.md` | `bizs/README.md` 指向它 |

## 6. 接口清单

标注：🔓 = `@PublicApi`；🔑 = 仅需登录；其余为所需权限码。写操作均带 `@OperationLog`。

后台表格列表统一显示 ID 列并按 ID 降序作为默认顺序；分页接口需保证跨页 ID 降序。树形列表保持父子关系，同级节点按 ID 降序。前端表格至少保留一列弹性列并填满内容区，避免全部列固定宽度。

### 6.1 认证 `/api/auth`（system）

| 方法 | 路径 | 权限 | 请求 | 响应 data |
| --- | --- | --- | --- | --- |
| POST | /login | 🔓 | `{username, password}`；可选请求头 `X-Auth-Mode: token` | 默认（浏览器）：`{tokenType:"Bearer", expiresIn(秒), userId}`，令牌只通过 `Set-Cookie` 下发 `weiran_token` 与 `weiran_csrf`（见 §4），响应体**不含** `accessToken`；带 `X-Auth-Mode: token`（脚本 / 非浏览器）：`{accessToken, tokenType:"Bearer", expiresIn, userId}`，**不写** Cookie，之后用 Bearer 头调用 |
| POST | /logout | 🔑 | —（Cookie 认证时需带 `X-CSRF-Token`） | `{ssoLogoutUrl: string \| null}`（写登出日志）；响应以 `Max-Age=0` 清除 `weiran_token` 与 `weiran_csrf`。本次会话来自配置了登出的外部身份提供方时 `ssoLogoutUrl` 为其登出地址（回跳 `<public-base-url>/login`），前端整页跳转；否则为 null |
| GET | /me | 🔑 | — | `CurrentUserView{id, username, nickname, email, phone, avatar, gender, departmentId, departmentName, roles:string[], permissions:string[], hasPassword:boolean}`；超管 permissions 返回 `["*"]`；`hasPassword=false` 表示没有本地密码（外部身份自动开通的用户），此时密码登录、`/verify-password` 一律 40101，`PUT /password` 返回 40000「未设置本地密码」 |
| GET | /menus | 🔑 | — | 当前用户可见菜单树 `MenuNode[]`（仅 directory/menu，status=enabled；超管=全部；visible=false 的也返回，前端据此只注册路由不显示） |
| PUT | /profile | 🔑 | `{nickname, email?, phone?, avatar?, gender?}` | null |
| PUT | /password | 🔑 | `{oldPassword, newPassword}`（新密码 8–64 位，含字母与数字） | null；成功后 token_version+1，前端需重新登录 |
| GET | /preferences | 🔑 | — | 当前用户的界面偏好对象（原样返回存储的 JSON 对象）；从未保存过返回 `null` |
| PUT | /preferences | 🔑 | 任意 JSON **对象**（序列化后 ≤ 16KB；非对象或超限 40000） | null；全量覆盖。**不记操作日志**（前端 500ms 防抖高频写入） |
| GET | /favorite-menus | 🔑 | — | 收藏的菜单 id `number[]`（按收藏顺序；已删除或当前用户已无权访问的菜单自动过滤掉） |
| PUT | /favorite-menus | 🔑 | `{menuIds: number[]}`（重复 id **静默去重、保留首次位置**；去重后 ≤ 50 个；每个 id 必须是当前用户可访问的 enabled `type=menu` 菜单，否则 40000） | null；全量覆盖 |
| GET | /providers | 🔓 | — | `{passwordLoginEnabled: boolean, providers: [{id, type: "oidc"\|"cas", name}]}`；只含已启用的提供方，不含任何密钥与地址 |
| GET | /sso/{provider}/authorize | 🔓 | 查询 `redirect`（站内路径，以单个 `/` 开头，否则视为 `/`）、`mode=login\|bind`（bind 需已登录，否则 302 `/login?ssoError=40100`） | 302 到外部身份提供方；下发签名的流程 Cookie `weiran_sso`（HttpOnly、SameSite=Lax、Path=/api/auth/sso、600s） |
| GET | /sso/{provider}/callback | 🔓 | OIDC：`code`、`state`（或 `error`）；CAS：`ticket`、`state` | 成功：login 模式下发 `weiran_token` / `weiran_csrf` 并 302 到 redirect；bind 模式 302 到 `/profile?bound=<provider>`。失败：302 到 `/login?ssoError=<code>`（bind 模式为 `/profile?ssoError=<code>`），code ∈ 40102 / 40303 / 40301 / 40100 / 40901。无论成败都清除 `weiran_sso` |
| GET | /identities | 🔑 | — | 本人外部身份 `[{id, provider, providerName, externalId, displayName, createdAt}]` |
| DELETE | /identities/{id} | 🔑 | — | null；没有本地密码且只剩这一个外部身份时 40901（防锁死）；记操作日志 |
| POST | /verify-password | 🔑 | `{password}`（空值 40000） | 正确返回 null；错误 `40101`、message「密码错误」（前端锁屏解锁用；**不改变**令牌与 token_version，**不写**登录日志） |

**外部身份登录（D-015）**：提供方用 `weiran.auth.providers.<id>.*` 配置（环境变量 `WEIRAN_AUTH_PROVIDERS_<ID>_*`，见 `02-部署.md`），类型 `oidc`（授权码 + PKCE + state + nonce，id_token 经 JWKS 验签）或 `cas`（3.0 `/p3/serviceValidate`）。
外部身份只按 `(provider, external_id)` 映射本地用户；未绑定时按提供方 `auto-provision` 决定拒绝（40303）或自动开通（无本地密码、默认角色），**不自动关联同名本地用户**。外部登录签发的仍是本地 JWT（多一个 `idp` claim）。
`weiran.auth.password-login.enabled=false` 时只有内置超管能用密码登录，其余 40304。对外地址 `weiran.auth.public-base-url`（`WEIRAN_PUBLIC_BASE_URL`）用于拼回调与登出回跳，不从请求头推断。

登录规则：用户名不存在与密码错误**同一个错误码 40101**（防枚举）；禁用账号 40301；成功/失败都写 `sys_login_log`；
成功后更新 last_login_at/ip。JWT：HS256，claims `sub`=userId、`username`、`ver`、`iss`、`aud`，有效期默认 12h，密钥 ≥ 32 字节，缺失则启动失败。
`iss` 缺失、不认识或 `aud` 不含本系统的令牌一律 40100。配置键 `weiran.auth.jwt.secret|ttl|issuer|audience`（环境变量
`WEIRAN_JWT_SECRET|TTL|ISSUER|AUDIENCE`，`issuer` / `audience` 默认 `weiran4j`）；2026-10-05 起由 `weiran.system.jwt.*` 改名而来（D-014），
改名后此前签发的令牌（没有 `iss`）全部失效，需要重新登录。
基座对外另有只校验凭据、不签发令牌的 `AuthService.authenticate(username, password, client)`：规则与登录相同（同一 40101、失败写日志、禁用 40301），
成功时不写成功日志——登录接口复用它，供将来的外部身份登录使用。

`MenuNode = {id, parentId, title, type, path, component, icon, permission, sort, visible, keepAlive, isExternal, status, children: MenuNode[]}`

偏好字段的定义（44 个，含默认值）以前端 `web/src/hooks/usePreferences.tsx` 为唯一事实源；后端只存不校验字段含义。
Flyway：`V202609270001__system_user_preferences.sql`（system 模块）给 `sys_user` 追加 `preferences`、`favorite_menus` 两列。
`sys_user.updated_at` 只反映资料 / 状态 / 角色 / 密码等真实变更：登录、偏好与收藏的保存**不刷新**它。MySQL JSON 列会重排对象键顺序，前端不要依赖偏好对象的键序。

| GET | / | system:user:list | 分页；查询参数见下表，全部可选、缺省或空白即不过滤、全部条件取交集 → `UserView[]`（按 id 降序） |
| GET | /{id} | system:user:list | `UserView` |
| POST | / | system:user:create | `{username, nickname, password, email?, phone?, gender?, departmentId?, status?, roleIds: number[]}` → `{id}` |
| PUT | /{id} | system:user:update | 同上但无 username/password |
| DELETE | /{id} | system:user:delete | 内置用户与自己不能删（40901） |
| PUT | /{id}/password | system:user:reset-password | `{password}`；token_version+1 |
| GET | /options | 🔑 | 启用用户下拉 `[{id, username, nickname}]` |
| GET | /{id}/identities | system:user:identity | 该用户的外部身份，结构同 `/api/auth/identities` |
| POST | /{id}/identities | system:user:identity | `{provider, externalId, displayName?}` → `{id}`；provider 未配置 40000；该外部身份已绑定 40901；记操作日志 |
| DELETE | /{id}/identities/{identityId} | system:user:identity | null；管理员可解绑最后一个（前端二次确认）；记操作日志 |

`GET /api/users` 查询参数（高级筛选为单字段查询，每个参数只查自己那一列）：

| 参数 | 类型 | 匹配口径 | 非法值 |
| --- | --- | --- | --- |
| `keyword` | string | 用户名 / 昵称 / 手机三列模糊（OR） | — |
| `status` | string | 等值，`enabled` / `disabled` | 40000 |
| `departmentId` | number | 含全部子部门 | 40000（非数字） |
| `username` | string | 等值（去首尾空白） | — |
| `userId` | number | 等值 | 40000（非数字） |
| `phone` | string | 等值（去首尾空白） | — |
| `email` | string | 等值（去首尾空白） | — |
| `roleId` | number | 拥有该角色的用户（每人只出现一次） | 40000（非数字） |
| `gender` | string | 等值，`male` / `female` / `unknown` | 40000 |
| `createdStartTime` / `createdEndTime` | `yyyy-MM-dd HH:mm:ss` | `created_at` 闭区间，可只传一端 | 40000（格式错） |
| `lastLoginStartTime` / `lastLoginEndTime` | `yyyy-MM-dd HH:mm:ss` | `last_login_at` 闭区间，可只传一端；传任一端即排除从未登录的用户 | 40000（格式错） |

开始晚于结束不报错，返回空页。

`UserView = {id, username, nickname, email, phone, avatar, gender, departmentId, departmentName, status, isBuiltin, roleIds:number[], roleNames:string[], lastLoginAt, lastLoginIp, createdAt, updatedAt}`（**绝不返回 password / token_version**）

### 6.10 系统站点配置与媒体库 `/api/system/**`

管理端站点配置使用通用固定目录，服务端负责 key 与 ident 映射；`contents` 原样保存。站点配置支持 Tiptap 富文本编辑、粘贴图片和多选图片上传。图片上传同时登记到 `sys_media`，图片库只管理已登记资产。本站不提供公开站点内容读取或新闻读取接口。

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/system/site-config` | `system:site-config:list` | 返回 `{items: SiteConfigItem[]}`，每项 `{key, label, ident, contents}` |
| PUT | `/api/system/site-config` | `system:site-config:update` | 全量保存 `{items: [{key, contents}]}`；键集合必须符合固定配置目录；成功记录操作日志 |
| POST | `/api/system/media/images` | `system:media-library:upload` | multipart 字段 `file`；仅允许 jpg/jpeg/png/gif，最大 10 MB；返回 `{url, name, path, size}` |
| GET | `/api/system/media-library` | `system:media-library:list` | 分页查询已登记图片，可按原始文件名关键词过滤 |
| DELETE | `/api/system/media-library/{id}` | `system:media-library:delete` | 删除未被站点配置引用的媒体资产；引用中返回冲突 |

`SiteConfigItem = {key: string, label: string, ident: number, contents: string | null}`。站点配置页面按「站点介绍、协议、联系方式、首页素材」分 Tab 展示；富文本 HTML 原样保存。图片库允许一次选择多张图片，每张独立上传并显示结果；仍被任何站点配置 `contents` 引用的图片不可删除。管理 API 使用统一响应 `{code: 0, message, data}`。本契约不定义公开站点内容读取或新闻接口。

## 7. 前端（`web/`，仓库根目录）

对标 mono4ts `packages/web` 的**骨架**，不搬业务组件。

```
web/src/
├── main.tsx / App.tsx           # QueryClient、Semi LocaleProvider(zh_CN)、Router
├── config.ts                    # 读 VITE_APP_TITLE 等
├── utils/request.ts             # fetch 封装：Bearer、解包 {code,message,data}（code === 0 为成功，数字）、401 清令牌跳登录、Toast 错误
├── utils/page-registry.ts       # import.meta.glob('../pages/**/*.tsx') → 按菜单 component 懒加载
├── utils/icons.tsx              # lucide 图标名 → 组件（菜单 icon 字段）
├── hooks/useAuth.ts             # 令牌、me、login/logout
├── hooks/usePermission.ts       # hasPermission(code)；permissions 含 "*" 视为全部
├── hooks/queries/*.ts           # 每个资源一份 TanStack Query hooks（users/roles/menus/departments/dicts/configs/logs/auth）
├── components/                  # Permission(按钮级)、DictTag、DictSelect、DepartmentTreeSelect、IconPicker、SearchToolbar、StatusTag、PageContainer
├── layouts/AdminLayout.tsx      # 侧边栏（菜单树渲染）+ 顶栏（面包屑、用户下拉：个人中心/退出）+ 多页签(可关闭，右键关闭其它) + 内容区
└── pages/
    ├── login/LoginPage.tsx
    ├── dashboard/DashboardPage.tsx      # 欢迎页 + 当前用户信息卡片
    ├── profile/ProfilePage.tsx          # 修改资料、修改密码
    ├── forbidden/ForbiddenPage.tsx · not-found/NotFoundPage.tsx
    ├── system/{users/UsersPage, roles/RolesPage, menus/MenusPage, departments/DepartmentsPage, dicts/DictsPage, configs/ConfigsPage}.tsx
    └── logs/{LoginLogsPage, OperationLogsPage}.tsx
```

- **路由由菜单驱动**：登录后拉 `/api/auth/menus`，对 type=menu 且 component 能在 page-registry 找到的节点注册路由；
  找不到组件的菜单渲染「页面不存在」占位，不崩溃。`/login`、`/profile`、`/403`、`*` 是静态路由。
- 按钮权限：`<Permission code="system:user:create">…</Permission>` 或 `hasPermission()`。
- dev server 端口 `VITE_PORT`（默认 5373），`/api` 代理到 `VITE_API_PROXY_TARGET`（默认 `http://localhost:3310`）。
- 主色 `#0064FA`（与 mono4ts 一致）。
- 测试：vitest + jsdom + @testing-library/react；断言 Semi `Form.*` 控件时必须包 `<Form>`。
