# Proposal

## Why

- 背景：站点配置需要支持富文本编辑与图片上传；图片文件需要集中查询、复用和安全删除。
- 业务目标：编辑人员可在站点配置中编辑富文本，并在统一图片库批量上传、检索、复用与安全删除图片。
- 当前问题：上传对象只有临时返回值，没有可分页检索的持久元数据；直接删除可能造成仍被站点配置引用的图片失效。
- 需求来源：见 `interview.md`。

## What Changes

- 新增：图片资产索引和后台图片库，支持多图上传、浏览、按文件名搜索、预览、复制 URL、引用保护和删除。
- 改造：站点配置富文本文件选择器支持多选；上传图片统一登记为媒体资产。
- 改造：站点配置读写接口与图片上传/管理接口统一使用 `/api/system/**` 路径。
- 改造：system 文件存储提供本地与 OSS 上传、读取和经过对象路径校验的删除操作。
- 复用：现有 Tiptap 编辑器、框架分页、权限与操作日志；文件存储实现归入 system 模块。
- 明确不做：新闻管理/新闻读取；历史对象扫描或回填；自动清理孤儿图片；图片裁剪/压缩/转码或非图片管理。

## Scope

### In Scope

- 站点配置富文本图片上传登记；多选图片后按选择顺序插入编辑器光标位置。
- 图片资产持久化、批量上传管理页面、分页/关键词搜索、预览/复制 URL、引用保护与删除。
- 接口统一归入 system API 路径：站点配置使用 `/api/system/site-config`；图片上传使用 `/api/system/media/images`；图片管理使用 `/api/system/media-library/**`。
- 新增 system Flyway 媒体迁移和后台图片库菜单/权限种子。
- 更新站点配置、文件存储、媒体库能力规格与表现状文档。

### Out of Scope

- 不迁移新闻管理、新闻后台或前台新闻读取。
- 不包含移动端应用页面或上传行为。
- 不修改统一契约或已合入的 Flyway 脚本；文件存储配置统一由 system 模块提供。
- 不做图片裁剪、压缩、转码、视频/非图片文件管理或对象存储迁移。
- 旧对象的自动扫描与历史图片元数据回填。

## Dependencies

- 产品/设计：使用现有后台页面骨架、列表与上传交互。
- 后端：system 五层、现有站点配置服务和文件存储。
- 前端：React、Semi UI、TanStack Query、现有 Tiptap 依赖。
- 数据库变更：只追加 system Flyway 脚本；迁移前核对菜单 id。
- 运维/配置：通过 system 存储配置提供本地/OSS 模式与必要的对象存储参数。
- 测试：domain/application/infrastructure/adapter 测试、前端编辑器/页面测试、system 集成测试。

## Risks

| 风险 | 触发场景 | 应对方案 |
|---|---|---|
| 引用检查与保存竞态 | 图片删除与站点配置保存并发 | 两类事务按 ident 升序锁定相同的 `sys_site_config` 配置行，再检查/写入，避免新增专用锁表 |
| 存储删除成功但数据库删除失败 | 对象存储与媒体记录短暂不一致 | 删除期间保留状态记录；存储失败恢复记录并报错 |
| 图片库不显示历史对象 | 历史对象没有元数据记录 | 明确只管理新登记对象；不猜测或回填旧对象 |
