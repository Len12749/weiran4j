# Interview

## 一句话需求

> 系统配置改为 字典管理的方式, 分组放在左边, 内容放在右边
> 系统配置分组使用字典组扩充, 改为 sys_group, type:config,dict , 并且支持后续可复用

## 澄清记录

| # | 提问 | 回答 | 由此确定的决策 |
|---|---|---|---|
| 1 | `sys_dict` 与 `sys_group` 的关系是什么？ | 用户补充：二者合并，保留 `sys_group` | `sys_group` 成为唯一分组表；字典记录使用 `type=dict`，配置分组使用 `type=config` |
| 2 | 字典项的关联列是否同步改名？ | 用户补充：`sys_dict_item.dict_id` 改为 `group_id` | 数据库列改名并保留关联值；现有 HTTP 字段 `dictId` 保持兼容 |
| 3 | 配置 API 是否迁移到 system 路径？ | 用户补充：`api/config/**` 改为 `api/system/config/*` | 所有配置 API 统一使用 `/api/system/config` 前缀，并按模块 / 资源 / 动作组织路由 |
| 2 | 配置页面的布局是什么？ | 分组在左，内容在右 | 采用主从式双栏布局，并复用 `NavListPanel` |

## 边界

### 要做

- 将 `sys_dict` 合并/迁移为 `sys_group`，不再保留 `sys_dict` 表；类型至少支持 `config` 与 `dict`。
- 字典记录保留为 `type=dict`，配置分组使用 `type=config`；查询和写入必须按类型隔离。
- 保留 `sys_dict_item` 及既有字典 API 行为，数据库列 `group_id` 关联分组 ID。
- 配置管理页面改为左侧分组、右侧配置项内容，保留动态字段表单与配置项操作。
- 配置分组条目与字段管理侧栏保持一致，显示创建时间、内置状态和是否可删除，并按权限提供删除操作。
- 所有配置 API 路径迁移为 `/api/system/config/{action}[/{id}]`，采用模块 / 资源 / 动作语义。
- 同步接口契约、迁移、前端类型和状态文档。

### 明确不做

- 不改字典管理页面和字典 API 路径；字典元数据底层改存 `sys_group`。
- `sys_dict_item.group_id` 保留原关联值；现有 HTTP 字段 `dictId` 保持兼容。
- 不改变配置键前缀、配置字段元数据、匿名读取规则和配置项权限。
- 配置 API 路径迁移后不保留旧路径别名。

### 本次不决定(留给后续 change)

- `sys_group.type=dict` 以外的后续分组类型与消费方。
- 自定义配置分组仅在组内没有配置项时允许删除；内置分组始终不可删除。

## 验收标准

- [ ] AC-1 `sys_group` 表支持 `config`、`dict` 类型，且组编码只在同类型内唯一。
- [ ] AC-2 已有配置分组迁移到 `sys_group`，系统配置的分组查询只返回 `type=config`。
- [ ] AC-3 配置新增、修改时，后端仅接受存在且类型为 `config` 的分组编码。
- [ ] AC-4 系统配置页面左侧显示分组导航，选择分组后右侧显示该组配置项。
- [ ] AC-5 原有配置动态表单、权限控制、保存与删除行为保留。
- [ ] AC-6 契约、前端 API 类型、状态文档与新接口和数据结构一致。
- [ ] AC-7 所有配置请求均使用 `/api/system/config/{action}[/{id}]`，旧 `/api/configs/**` 路径不再注册。

## 关键取舍

| 取舍点 | 选择 | 放弃的方案 | 理由 |
|---|---|---|---|
| 通用分组模型 | 将 `sys_dict` 转为 `sys_group`，以 `type` 区分 config/dict | 保留两张并行主表或继续使用固定枚举 | 避免重复模型，同时保留字典功能 |
| 分组呈现 | 左侧导航列表、右侧内容 | Tab | 与字典管理主从布局一致，便于组多时纵向浏览 |
| 字典改造范围 | 数据模型并入 `sys_group`，字典 UI/API 保持原有行为 | 保留 `sys_dict` 独立表 | 让字典和配置共用分组表，同时控制本次前端范围 |

- 无

## 对下游的硬约束

- 表结构只新增 Flyway 迁移；已发布迁移不修改。
- 配置组编码需保持既有 `general`、`user` 值，迁移后已有配置不得丢失或错组。
- 迁移必须保留字典/字典项 ID、编码、状态和审计信息。
- 迁移必须保留字典项关联值，只改 `dict_id` 列名为 `group_id`。
- 避免新增组 CRUD API；如实现过程中发现必须新增，返回 L2 重新设计。
