# Design

## Context

需求与最终编号见 `interview.md`，现有实现与影响面见 `explore.md`。错误码从五位状态前缀迁移到六位 `{服务}{资源}{错误}`，通用、系统、地区分别为 `10`、`11`、`12`。

## 宪法对照

| 原则 | 判定 | 说明 |
|---|---|---|
| CP-1 领域层不依赖框架 | ☑ | 领域层只使用纯 Java 错误码契约 |
| CP-2 依赖方向单向向内 | ☑ | 枚举留在 framework 或模块 api，无反向依赖 |
| CP-3 持久化类型不跨层 | ☑ | 错误码不引入 DO、Mapper 或 IPage |
| CP-4 版本号只有一个来源 | ☐ | 不改依赖版本 |
| CP-5 质量规则只在 build-logic 里配置 | ☐ | 不改质量规则 |
| CP-6 豁免必须最小且带理由 | ☐ | 不新增豁免 |
| CP-7 表结构只经 Flyway 迁移变更 | ☑ | 操作日志响应码仍为 int，不改表结构或历史迁移 |
| CP-8 密码只用 BCrypt，令牌吊销只走 token_version | ☑ | 仅换错误码，不改变认证与吊销逻辑 |
| CP-9 凭据不进版本库、不进日志 | ☑ | 不记录额外凭据，沿用安全日志 |
| CP-10 认证失败不泄露账号存在性 | ☑ | 用户名不存在与密码错误继续共用 `110101` |
| CP-11 错误码归属决定 HTTP 状态 | ☑ | `httpStatus()` 保持独立，Controller 不按码推断状态 |
| CP-12 依赖只能业务 → 基座 → 框架 | ☑ | 地区在自身 api 定义专属码，不依赖基座实现 |
| CP-13 业务只经基座的 weiran-system-api 接触基座 | ☑ | 地区不读基座内部类型 |
| CP-14 错误码按号段分配 | ☑ | 通用 10、系统 11、地区 12，并登记在 `business-modules.md` |
| CP-15 权限码、菜单 id 与 Flyway 模块段按层隔离 | ☐ | 不新增权限码、菜单或迁移 |

## Architecture

统一 `ErrorCode` 定义数字码、HTTP 状态和消息。框架通用码可被各模块复用；系统认证和地区业务在各自 api 枚举中定义专属码。全局异常处理器从错误定义取得 HTTP 状态及数字码。前端按数字码识别会话失效、凭据错误和 SSO 错误。

| 归属 | 旧码 → 新码 |
|---|---|
| 通用 | `40000→100001`、`40100→100101`、`40300→100102`、`40302→100103`、`40400→100002`、`40900→100003`、`40901→100004`、`50000→100005`、`50300→100006` |
| 系统认证 | `40101→110101`、`40102→110102`、`40301→110103`、`40303→110104`、`40304→110105`；手机号场景使用 `110106`、`110107` |
| 地区 | `40020→120101`、`40920→120102`、`40921→120103` |

## Data Flow

1. 业务抛出包含 `ErrorCode` 的异常。
2. 全局异常处理器使用 `code()` 输出六位数字，使用 `httpStatus()` 输出状态。
3. 操作日志保存数字响应码；前端请求层按新码处理会话及提示。

## 跨模块契约变更(DS-1)

| 对象 | 动作 | 消费方 |
|---|---|---|
| `CommonErrors` | 通用码换为服务 10；资源 00/01 不变 | 全部后端模块、web |
| `ErrorCode` | 保留 int 与独立状态接口，注释更新六位语义 | 全部后端模块 |
| 分页与响应包络 | 不改结构和类型 | 全部模块、web |

## API Design(DS-2)

不新增路由。失败体仍为 `{code, message, data, requestId}`，其中 `code` 是六位数字；成功体的 `code` 仍为数字 `0`。原有 HTTP 状态保持不变。

## Database Design(DS-3)

不改表结构。`sys_operation_log.response_code int` 足以保存六位码；既有历史日志保留原值，时间区分新旧格式。不修改已发布 Flyway 脚本。

## 权限与已知缺口(DS-4)

权限判定和权限码保持原行为。会话失效与凭据错误仍分别处理；无新增写接口、菜单、租户、数据范围或任务机制。

## 分层与装配(DS-5)

框架定义跨模块通用码，system 与 region 在各自 api 定义专属码，应用服务引用所属模块的错误码。不新增模块或自动配置。

## 前端设计(DS-6)

请求层以 `100101` 判断会话失效，以 `110101` 区分密码错误；SSO 提示使用新的系统码。地区错误只经普通错误展示。对冲突响应使用 HTTP 409 或具体冲突码，不依赖旧码的数值区间。

## Observability

请求号与响应码继续写入异常日志和操作日志。登录日志行为不变；可按新六位码检索上线后的错误。

## Test Plan

| 层级 | 范围 | 命令 |
|---|---|---|
| 后端 | 码值唯一、前缀、HTTP 状态与接口行为 | `./gradlew check --no-daemon`（JDK 21） |
| 前端 | 会话、SSO、错误展示 | `pnpm test`、`pnpm lint`、`pnpm build` |
| 规格 | delta 与现行规格一致 | `node openspec/check.mjs` |

## Rollout Plan

后端与前端同步部署；操作日志新增记录自动使用新码，无数据库迁移。发布说明列出旧码到新码的映射。

## Rollback Plan

以实施提交为 revert 锚点回退后端与前端。操作日志中的新旧码都是整数，回退无需数据库变更；历史记录按发生时间对应版本解释。
