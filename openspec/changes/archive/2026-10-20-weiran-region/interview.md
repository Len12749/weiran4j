## 边界

### 要做

- 新建 `weiran-region` 五层业务模块，管理省、市、县三级行政区划，区划代码使用字符串保存以保留前导零。
- 提供地区树、平铺列表、详情、创建、更新、删除及按名称/代码、级别、状态筛选；父级层级必须正确，禁止自父级、后代循环和删除仍有子级的地区。
- 提供只需登录即可读取启用地区树的级联选择器 API，以及可按当前筛选条件导出全部匹配结果的 CSV 下载。
- 提供地区管理页面：树表格、筛选、展开/折叠、增删改、启停、导出与按钮权限控制。
- 通过 Flyway 初始化源项目 `china-division@2.7.0` 的 31 个省级、342 个地级、2978 个县级记录；后续更新数据采用追加迁移。
- 使用 `region:` 权限前缀并登记 `weiran-region` 的菜单、按钮权限、错误码序号段、菜单 ID 段。
- 同步 API 契约、前端 API 类型、列表规范、模块现状文档及业务模块索引。

### 明确不做

- 不提供行政区划文件上传或批量导入页面；源模块没有这项管理能力。
- 不扩展街道、乡镇、村级数据；初始化范围与源模块一致，为省、市、县三级。
- 不在本 change 将区划字段接入用户、部门或其他业务表；级联选择器作为独立可复用组件交付。
- 不引入通用导出中心或 XLSX 依赖；导出仅实现地区筛选结果的 UTF-8 CSV 下载。

### 本次不决定(留给后续 change)

- 后续民政部区划数据的版本更新节奏与自动同步机制。
- 是否让其他业务页面持久化完整区划路径或关联地区主键。

- [ ] AC-4 创建或移动地区时拒绝不存在或层级错误的父级、环引用和重复区划代码；删除有子地区的节点被拒绝。

## 关键取舍

| 取舍点 | 选择 | 放弃的方案 | 理由 |
|---|---|---|---|
| 模块层级 | 独立 `weiran-region` 业务模块 | 并入 `weiran-system` | 行政区划属于可复用业务数据，基座不得依赖特定业务；符合三层依赖边界。 |
| 权限前缀 | `region:` | 沿用源模块 `system:region:` | 行政区划属于业务模块，不能占用基座 `system:` 权限空间。 |
| 初始数据 | 固化 `china-division@2.7.0` 数据到新增迁移 | 应用启动时下载第三方 JSON | 确保部署离线可启动、迁移可审计且不会随依赖升级静默改变数据。 |
| 导出 | 当前筛选的 UTF-8 CSV | 接入 XLSX 导出中心 | 本仓没有通用导出中心；避免为单个地区模块引入导出子系统或新运行时依赖。 |
| 管理树排序 | UI 同级节点按 ID 倒序 | 直接沿用源项目的 sort/code 顺序 | 遵守本仓库现行列表规范；级联选择器仍按业务排序字段与区划代码排序。 |
