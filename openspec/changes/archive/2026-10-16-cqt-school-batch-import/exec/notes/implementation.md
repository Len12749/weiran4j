# 学校作品批量导入实现记录

## 已确认的接口行为

- 旧 uniapp 的模板下载使用 `window.open`，因此模板文件端点公开；任务、作品和上传登记仍从 portal token 取得学校账号。
- uniapp 上传登记只传存储 URL，不传原始文件名；服务端从 URL 补出文件名，确认接口再接收旧页面传来的 ZIP/Excel 名称。
- 旧客户端确认请求含 `userid`，该字段不参与身份或任务归属判断。
- 任务列表继续提供 `data.data[]`，详情提供 `results[]`；状态码映射与旧页面消费一致。

## 导入字段与评价边界

- 示例文件第 2 行为表头，真实内容共解析 10 行；第 7 列所在学校、第 8 列联系方式按表头映射。
- 导入与空白模板只处理到“渠道标识”的 20 列；后两列省赛/国赛奖项不读取、不校验、不持久化。
- 省赛/国赛评价属于作品提交后的处理阶段；本 change 不建设该评价流程或国赛作品入口。

## 安全与恢复

- 导入只打开当前账号拥有的本地/OSS 对象，不把用户 URL 当作任意 HTTP 地址抓取。
- ZIP 在内存流中扫描并按规范化 basename 唯一匹配；拒绝路径穿越、重复同名附件、过多条目和超量展开数据。
- 任务以数据库租约领取，租约过期可再次领取；行结果唯一约束与作品指纹支持恢复和重复确认。

## 验证

- Gradle 统一门禁必须用 JDK 21，并先执行 `spotlessApply`；依赖下载使用临时 repo1 Maven Central 镜像 init script。
- POI 5.5.1 与 CQT Excel 读取/模板生成验证通过；依赖版本漂移按 D-013 在业务依赖清单登记。
