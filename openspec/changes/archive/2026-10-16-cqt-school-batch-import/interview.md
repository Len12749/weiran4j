# Interview

## 澄清记录

| # | 提问 | 回答 | 由此确定的决策 |

| 1 | 需要优先推进哪项已知缺口？ | 用户要求继续推进，并提供学校报名示例 Excel | 优先实现 `cqt_entries.md#03` 中的学校批量导入切片，继续复用 uniapp 现有页面和 CQT 报名领域模型 |
| 2 | Excel 模板是什么？ | 用户提供 `openspec/state/files/00-【报名示例】报名表-第二届“常青藤”全国青少年校园戏.xlsx` | 以工作表「报名表」第二行为表头，不依赖旧代码推断的数组索引；数据列共 22 项，联系方式在索引 7、学校在索引 6 |
| 3 | 附件列如何解释？ | 模板列名为「附件名称/百度网盘链接」；示例中「链接」行是 URL，「文件」行是文件名 | 暂按链接类型直接使用 URL，文件类型按文件名在 ZIP 中匹配；最终匹配规范在 design 中冻结 |
| 4 | 团体行如何分组与校验？ | 用户明确赛项、专业、作品名称和团体人数需要数据验证；样例中同名作品分成 4 人与 2 人记录 | 逐行消费团体成员；同一作品组要求赛项/专业/作品名/人数一致，人数 N 对应恰好 N 条成员记录；达到 N 后下一条开始新组 |

## 边界

### 要做

- 实现 uniapp 学校批量导入实际使用的模板地址、待处理检查、学校作品列表、ZIP/Excel 上传登记、确认导入、导入任务列表与详情接口。
- 以示例 Excel 的表头映射数据，支持个人行、团体成员、附件链接与 ZIP 附件，并持久化任务与逐行结果。
- 校验赛事、赛项/专业、作品名称及团体人数；同一团体的成员行按连续 N 行组成一个作品组，组内上述字段一致。
- 在 `/api-web/**` 提供 portal 接口；校验学校账号、赛事范围和任务所有权；复用现有报名、文件存储及参赛唯一键规则。
- 使异步任务进度和结果可查询；修正 uniapp 成功/失败记录显示中的模板列错位。

### 明确不做

- 不实现学生个人报名表单、报名修改/撤回、评审/奖项/成绩/证书、后台赛事与作品管理。
- 不读取或校验导入模板中的省赛奖项、国赛奖项列；赛事阶段评价在作品导入之后处理。
- 不新增后台管理菜单或后台批量导入页面。
- 不改上游文件；只在 `AGENTS.biz.md` 许可的 CQT、uniapp、业务脚本和 OpenSpec 下游范围内实现。

### 本次不决定（留给后续 change）

- 学校批量导入以外的已知缺口（`cqt_entries.md#01`、`#02`、`#04`）。
- 历史数据重复参赛去重与全量数据回填。

## 验收标准

- [ ] AC-1 学校账号可获取模板地址；个人账号、未登录请求不能创建或查询学校导入任务。
- [ ] AC-2 接口路径、方法、参数和返回结构与 uniapp 页面消费方式一致；任务仅对所属学校账号可见。
- [ ] AC-3 使用示例模板上传后，表头映射按列名识别，个人/团体、附件链接/ZIP 文件结果与输入相符；手机号取联系方式列，学校取所在学校列。
- [ ] AC-4 导入任务可持久化运行状态、进度、成功/失败数、附件匹配统计及逐行原始数据/错误；服务重启后任务不丢失或重复写入作品。
- [ ] AC-5 Excel 中无效作品不会阻断其他合法作品；团体人数与成员行数、赛项/专业/作品名称一致性经过校验；重复参赛受现有唯一键规则保护；任务和明细接口只泄露当前学校自己的数据。
- [ ] AC-6 uniapp H5 通过项目 pnpm 命令构建，后端集成测试验证上传、确认、异步处理、任务结果和所有权边界。

## 关键取舍

| 取舍点 | 选择 | 放弃的方案 | 理由 |
|---|---|---|---|
| Excel 列识别 | 以模板实际表头映射字段 | 固定数组序号 | 列顺序变化时不应把学校误显示为手机号；当前模板联系方式在 0 起始索引 7 |
| 任务执行 | 持久化异步任务和逐行明细 | 单请求同步导入或仅进程内任务 | 页面已有任务列表/详情，批量数据需要可恢复状态和错误追踪 |
| 业务入口 | 复用现有 CQT 报名领域与唯一键约束 | adapter 直接写业务表 | 保持报名校验、写入事务和阶段规则一致 |

## 对下游的硬约束

- 前台统一响应 HTTP 200，业务包络 `{code:200,message,data}`；未登录用 body `code:401`。
- 所有数据库对象使用 `cqt_` 前缀，Flyway 只追加；业务接口只放 `weiran-cqt`。
- 不信任客户端提供的 `userid`；账号身份从 portal token 解析。
- Excel/ZIP 文件由现有 `/api-web/local-files/upload` 保存；导入只接受本服务配置的存储 URL，解压必须防路径穿越并限制条目数与展开大小。
