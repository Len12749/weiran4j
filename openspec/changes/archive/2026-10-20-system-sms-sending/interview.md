# Interview

> **L0 · 消歧**。deep-interview 的落盘产物，是 `explore.md` 和 `proposal.md` 的唯一输入。

## 一句话需求

> 把这个项目中阿里云短信发送的能力接到本项目中来，放到 system 模块。

## 澄清记录

| # | 提问 | 回答 | 由此确定的决策 |
|---|---|---|---|
| 1 | system 里要提供哪种可调用边界？ | 用户要求将短信发送能力放入 system；按通用基座边界采用推荐方案 | 提供仅供业务模块调用的 `weiran-system-api` 服务契约；不增加公开 HTTP 验证码接口，验证码策略留给业务模块。 |

## 边界

### 要做

- 将源项目的阿里云短信发送适配能力移植到本项目 `weiran-system`。
- 使用 system 配置前缀和环境变量；敏感凭据不进入仓库或日志。

### 明确不做

- 不把源项目 `weiran-cqt` 的账号注册、登录、密码重置业务移入 system。
- 不改变当前项目的认证流程或增加短信登录。

### 本次不决定(留给后续 change)

- 验证码生成、校验、过期与频率限制由具体业务模块定义，本 change 不决定这些业务策略。

## 验收标准

- [ ] AC-1 `weiran-system-api` 提供业务模块可调用的短信发送契约，不增加公开 HTTP 验证码接口。
- [ ] AC-2 在 aliyun 模式下，system 能调用阿里云 SendSms；缺少必填配置时应用启动失败，错误信息不含密钥值。
- [ ] AC-3 发送结果区分成功、服务商频控、号码非法与其它失败；SDK 调用不自动重试。
- [ ] AC-4 AccessKey 不进入任何日志，手机号按掩码记录；aliyun 不记录模板参数，显式 log 模式记录模板内容。
- [ ] AC-5 disabled 模式保持默认且不触发真实短信发送。
- [ ] AC-6 log 模式记录模板代码和参数、返回 `LOGGED`，不调用外部服务。

## 关键取舍

| 取舍点 | 选择 | 放弃的方案 | 理由 |
|---|---|---|---|
| 短信业务职责 | 仅迁移可复用发送能力，账号业务留在业务模块 | 将源项目 CQT 账号流程整体移入 system | system 是通用基座，不应承载特定业务账号流程。 |

## 对下游的硬约束

- 阿里云 AccessKey 只从环境变量读取；日志与异常不得包含密钥值或验证码。
