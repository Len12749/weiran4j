# administrative-regions Specification

## Purpose
行政区划能力为后台业务提供统一、可维护的中国省市县三级地区数据，并通过稳定的区划代码支持地区检索、管理和级联选择。该能力独立于用户、部门等具体业务，供多个业务页面长期复用。

## Requirements

### Requirement: [FR-001] 三级行政区划数据

地区服务 **MUST** 以字符串区划代码维护省、市、县三级行政区划，并以父级区划代码表达层级关系。

#### Scenario: 初始化行政区划快照
- **WHEN** 新环境首次执行地区模块数据库迁移
- **THEN** 数据库包含 `china-division@2.7.0` 快照中的 31 个省级、342 个地级和 2978 个县级地区，区划代码唯一且每个非省级地区的父级存在并满足层级递进。
- **判据**: 对 `region` 查询按 `level` 分组的数量为 31、342、2978；无重复 code、孤立父级或错误层级。

### Requirement: [FR-002] 地区树与筛选查询

地区管理 API **MUST** 提供树形查询、平铺查询和按 ID 查询详情，并支持名称或区划代码关键词、级别、状态筛选；关键词命中后代时结果 **MUST** 保留其祖先路径。

#### Scenario: 查询筛选后的地区树
- **WHEN** 有地区管理权限的用户提交关键词、级别或状态筛选
- **THEN** 返回符合筛选条件的节点及其必要祖先，管理树同级节点按 ID 倒序展示。
- **判据**: API 响应仅包含匹配节点与其祖先；每组同级节点 ID 严格倒序。

#### Scenario: 查询平铺地区和详情
- **WHEN** 有地区管理权限的用户请求平铺列表或有效地区 ID 的详情
- **THEN** 平铺结果应用相同筛选条件，详情返回指定地区的完整业务字段。
- **判据**: 平铺响应不含 children 嵌套；详情响应 ID 与请求 ID 一致。

### Requirement: [FR-003] 地区层级维护

地区管理 API **MUST** 支持创建、更新和删除地区，并校验区划代码唯一、父级存在且层级正确、父级变更不会形成自引用或后代循环；删除有子级的地区 **MUST** 被拒绝。

#### Scenario: 创建或更新有效地区
- **WHEN** 有对应写权限的用户提交字段有效且层级关系合法的创建或更新请求
- **THEN** 地区被持久化，成功响应返回保存后的地区信息，且写操作被记录为操作日志。
- **判据**: 后续详情查询返回提交后的字段；操作日志存在对应成功动作。

#### Scenario: 拒绝非法层级变更或删除
- **WHEN** 请求使用重复代码、缺失或层级错误的父级、形成循环的父级，或删除仍有子级的地区
- **THEN** 请求以地区领域错误拒绝且数据保持不变。
- **判据**: API 返回对应 4xx 统一错误码；事务后原地区及其父子关系未改变。

### Requirement: [FR-004] 地区状态和权限

地区管理 API **MUST** 使用 `region:` 权限点保护管理查询、创建、更新、删除和导出；写操作 **MUST** 记录操作审计。启停地区 **MUST** 通过更新地区状态完成。

#### Scenario: 管理权限控制
- **WHEN** 无相应 `region:list/create/update/delete/export` 权限的用户访问地区管理端点
- **THEN** 请求被拒绝；有相应权限的用户可执行对应动作。
- **判据**: 缺少权限时响应 403；权限授权后同一合法请求成功。

### Requirement: [FR-005] 登录态地区级联选择

地区查询 API **MUST** 向已登录用户提供只包含启用节点及启用祖先链的地区树，地区选择组件 **MUST** 以省、市、县区划代码路径作为受控值。

#### Scenario: 获取可选地区树
- **WHEN** 已登录用户请求地区选择数据
- **THEN** 返回启用地区及其启用祖先组成的树，不要求地区管理权限；未登录请求按认证规则拒绝。
- **判据**: 普通登录用户可取得 lookup 响应；响应中不存在停用节点，未登录响应为 401。

#### Scenario: 选择省市县路径
- **WHEN** 用户在级联选择器中选择一个县级地区
- **THEN** 受控值包含省、市、县对应的区划代码路径，选项按地区 sort 与区划代码顺序展示。
- **判据**: 组件回调值的三段 code 与所选节点祖先关系一致。

### Requirement: [FR-006] 地区管理页面与导出

地区管理页面 **MUST** 提供地区筛选、树表格、展开折叠、增改删、启停和当前筛选结果 CSV 导出，并按权限显示操作；树表格 **MUST** 以 ID 为首列、同级 ID 倒序且保留至少一列弹性宽度。

#### Scenario: 管理和导出地区
- **WHEN** 管理员使用地区页面筛选、维护或导出地区
- **THEN** 页面呈现树形结果及有权限的操作；导出包含筛选后的全部匹配记录，不受当前展开状态影响。
- **判据**: UI 树同级 ID 倒序且表格有弹性列；CSV 行数与同条件全量 API 结果一致。

### Requirement: [FR-007] 地区接口契约和模块隔离

地区能力 **MUST** 作为独立五层业务模块自动发现，使用 `region` 业务表、`region:` 权限、已登记的菜单与错误码号段，并在架构接口契约和前端 API 类型中同步定义接口字段。

#### Scenario: 构建与契约同步
- **WHEN** 完成地区模块接入并运行项目检查
- **THEN** 五层模块参与 Gradle 构建，页面菜单组件路径有效，前后端契约字段一致且业务代码未访问基座内部持久化表。
- **判据**: `./gradlew check` 与 `node openspec/check.mjs` 通过；菜单路径能解析到页面；地区业务表名为 `region`。
