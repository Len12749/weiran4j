# system-media-library Specification

## Purpose
本能力长期负责后台图片资产的登记与维护：让内容编辑人员能够在一个位置批量上传、检索、复用和安全删除图片，并避免删除站点配置仍在引用的图片。

## Requirements

### Requirement: [FR-001] 媒体资产登记

站点配置和图片库上传的图片 **MUST** 在文件写入成功后登记到 `sys_media`，保存原始文件名、公开 URL、对象名、大小、上传人和创建时间；数据库失败时不得返回成功上传结果。图片资产表使用 `sys_` 前缀，图片上传接口 **MUST** 位于 `/api/system/` 路径下。

#### Scenario: 图片上传后持久可查
- **WHEN** 管理员通过站点配置编辑器或图片库上传有效图片
- **THEN** 图片写入当前文件存储且 `sys_media` 保存对应元数据
- **判据**:集成测试断言上传返回 URL 与媒体记录一致，刷新查询仍可找到记录

#### Scenario: 历史对象不伪造记录
- **WHEN** 查询图片库中此前已上传但没有媒体资产记录的对象
- **THEN** 图片库不猜测或虚构其名称、归属和大小
- **判据**:创建未登记的本地/OSS 对象后，媒体库查询不返回该对象

### Requirement: [FR-002] 图片资产检索

具备 `system:media-library:list` 权限的管理员 **MUST** 能通过 `GET /api/system/media-library` 按上传时间倒序分页查询媒体资产，并可按原始文件名关键词过滤。

#### Scenario: 分页并按名称搜索
- **WHEN** 管理员提交关键词、页码和页大小查询图片库
- **THEN** 返回匹配名称的资产、公开 URL、大小和创建时间及分页总数
- **判据**:接口测试断言过滤结果与分页元数据，前端测试验证搜索、分页和缩略图展示

### Requirement: [FR-003] 多图上传与复用

具备 `system:media-library:upload` 权限的管理员 **MUST** 能通过一次多文件选择上传多张 jpg/jpeg/png/gif 图片，每张不超过 10 MB；每张图片独立显示上传结果，失败项可重试。管理员 **MUST** 能预览图片并复制其 URL。每张图片通过 `POST /api/system/media/images` 单独上传。

#### Scenario: 一次选择多张图片
- **WHEN** 管理员一次选择多张有效图片上传
- **THEN** 每张图片都通过文件存储写入并登记，成功项显示在图片库，失败项可单独重试
- **判据**:前端测试断言所有选择项均触发上传且每个成功响应出现在查询列表；后端测试逐文件断言类型和大小校验

#### Scenario: 上传不支持或超限图片
- **WHEN** 管理员上传非 jpg/jpeg/png/gif 文件或超过 10 MB 的图片
- **THEN** 对应文件被拒绝且不会创建媒体资产
- **判据**:API 测试断言错误响应并检查数据库中无对应对象记录

### Requirement: [FR-004] 图片删除与引用保护

具备 `system:media-library:delete` 权限的管理员 **MUST** 能通过 `DELETE /api/system/media-library/{id}` 删除未被站点配置引用的登记图片；删除前 **MUST** 检查 `sys_site_config.contents` 是否包含目标 URL。只要站点配置仍引用目标 URL，系统 **MUST** 拒绝删除且不改变文件或媒体记录。删除与站点配置保存事务 **MUST** 按 ident 升序锁定相同的 `sys_site_config` 配置行，避免并发写入形成失效引用。文件对象删除 **MUST** 在数据库事务提交后执行；重复删除对象应安全，确保外部存储错误或数据库提交失败时资产记录仍可重试处理。

#### Scenario: 删除未引用的图片
- **WHEN** 图片 URL 未出现在站点配置内容中，且管理员有删除权限
- **THEN** 系统删除存储对象和媒体资产记录
- **判据**:测试断言对象不可访问、媒体查询不再返回该记录，操作日志包含删除事件

#### Scenario: 拒绝删除仍被站点配置引用的图片
- **WHEN** 站点配置原始 HTML 仍包含目标图片 URL
- **THEN** 系统返回冲突错误且保留存储对象与媒体资产记录
- **判据**:集成测试断言删除被拒绝且文件和记录仍存在

#### Scenario: 未授权删除
- **WHEN** 用户缺少 `system:media-library:delete` 权限或请求的媒体 id 不存在
- **THEN** 请求被拒绝或返回 not-found，文件存储与数据库内容不变
- **判据**:集成测试断言权限/错误响应以及文件和数据库状态
