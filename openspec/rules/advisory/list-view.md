# list-view.md —— 列表页（搜索栏 + 表格）约定

> **本文件没有机械守卫。** 唯一的唤起途径是 `AGENTS.md` 的规则索引表：**写或改 `backend/` 的列表页前读。**
>
> 视觉与交互的源头是设计稿 `wuli-design/testing.pen` 的「用户列表」画板及其笔记；
> 参考实现以 `backend/src/pages/system/users/UsersPage.tsx` 为主，展示高级筛选和用户专属查询；角色、配置、登录日志与操作日志页面也已接入通用搜索工具栏。
> 组件的接口与坑见 [`components.md`](components.md) 的 `SearchToolbar`、`TableActions`、`ColumnSettings` 条目，这里只写**约定**。
> 每条都写了「不这样做的症状」——这些问题几乎都不报错，只会在某个宽度、某份数据下才露出来。

## 一、搜索栏（`SearchToolbar`）

从左到右：**主操作 → 便捷搜索 → 搜索 / 重置图标按钮 → 高级筛选开关** ……（右侧）**工具按钮**。下方依次是高级筛选面板、已选条件。

1. **主操作放最左**（`leading`，如「新增用户」）。多个主操作时，第一个之后跟一个「…」更多按钮收纳其余的；**只有一个主操作时不放「…」**（设计稿笔记 1）。
   - 主操作按钮**只有文字、不带图标**（「新增用户」前面没有「+」，与设计稿一致）：`<Button type="primary" theme="solid">新增用户</Button>`。
2. **便捷搜索**是工具栏里常驻的 2～3 个常用条件（`children`）加其后的「搜索 / 重置」纯图标按钮（各自带 tooltip 和 `aria-label`，不显示按钮文字）。有高级筛选时，**窄屏（< 992px）隐藏整组便捷搜索——筛选控件与两个图标按钮一起隐藏**，只留主操作与高级筛选开关，查询改在面板里点「搜索」。
   - 症状（不隐藏）：窄屏下工具栏折成多行，表格被推到首屏以外。只隐藏输入框、留下搜索或重置按钮时，按钮失去了对应的输入，看起来像能操作却没有条件可填。
   - ⚠️ 代价：便捷搜索里有、高级面板里没有的条件（如用户页的「关键字」模糊搜索），窄屏下用不了。新列表页若有这类条件，要么也放进面板，要么接受。
3. **高级筛选**（`advanced`）：**默认收起**（设计稿笔记 2）；面板是 4 列栅格（< 992px 两列，< 576px 一列），每项用 `SearchField` 包一层（标签在上、控件在下）；底部「搜索 / 重置」。
   - **窄屏（便捷搜索被隐藏时）字段区限高**：只露两行（每项 58 + 行距 16），区内可纵向滚动（键盘 Tab 到被遮住的字段会自动滚进可见区），右下角「展开 / 收起」箭头按钮去掉 / 恢复限高；宽屏不限高、不显示该按钮。症状（不限高）：窄屏一展开面板，十个字段把表格推出好几屏。
   - **「搜索 / 重置」永远可点**：操作行放在字段区**之外**并吸底（`sticky`，抵消内容区 12px 底边距）。症状（放在字段区里）：限高时被裁掉；展开后面板比一屏高时滚出视口。
   - **高级筛选是单字段查询**：每个字段是独立的接口参数，各查各的列；不要把面板字段拼进一个模糊 `keyword`。
   - **面板只放后端查询接口已支持的条件。** 症状：Spring MVC 对**未声明的查询参数静默忽略**——多放一个后端不认的字段，界面上筛了、结果没变、不报错。
   - 与便捷搜索同名的条件**绑定同一份草稿**。症状（各存一份）：在面板里改了状态，工具栏里还显示旧值，点工具栏的查询又用回旧值。
   - **按天的时间范围**用 `utils/date.ts` 的 `toDayRange()`（补成当天 `00:00:00` / `23:59:59`），不要用 `toTimeRange()`（原样格式化，给日期时间选择器用）。症状：结束日当天创建的数据查不出来。
4. **右侧工具按钮按需出现，顺序固定**：展开树状 → 列设置 → 导出 → 刷新（设计稿笔记 3），没有的跳过。白底描边的方形图标按钮；列设置用**齿轮**图标。
   - **展开树状**只给树形表格（当前为菜单）：`treeExpand={{ expanded, onToggle }}`，在全部展开与全部收起之间切换；展开状态要受控（`expandedRowKeys`）。不要再放「全部展开」「全部收起」两个文字按钮。
   - **刷新**每个列表页都给（`onRefresh={() => void refetch()}`、`refreshing={isFetching}`）。
5. **已选条件**（`conditions`）：
   - 只反映**已生效**的条件（点过查询的那份），不反映正在输入的草稿。症状（用草稿）：还没点查询，标签就变了，和表格结果对不上。
   - 值给**可读文本**：下拉取选项名称（状态「启用」、角色名），时间显示「开始 ~ 结束」、单端「≥ / ≤」。症状（给原始值）：标签显示 `disabled`、`roleId: 2`。
   - 点 × 清掉该字段（**已生效条件与草稿一起清**）并**回到第 1 页**；有条件就显示「清空」（= 重置）。
6. 字号：搜索栏里的按钮与筛选控件与表格一致为 **13px**；已选条件整行（标签、「清空」）为 **12px**、标签高 22px。

## 二、表格

1. **ID 列与默认顺序**：每个表格列表都要显示 `ID` 列，默认按 ID 降序；服务端分页列表由后端保证跨页顺序。树表保留父子层级，每组同级节点按 ID 降序排列。ID 列放在最前，宽度足以显示完整 ID。症状（缺 ID 或按升序）：难以快速定位新建记录，跨页时最新数据不在前面。
2. **表格填满可用宽度**：表格占满内容区宽度；每张表至少保留一列不设置 `width`，让它吸收剩余空间。只给 ID、时间、状态等内容需要稳定宽度的列设宽度，不要把所有列都固定宽度。仍需用 `tableScrollX(columns)` 设置横向滚动阈值。症状（所有列固定且总宽小于视口）：表格停在内容区一侧，右侧留大块空白。
3. **表头与表体区分**：表头有背景色 `--color-table-head-bg`（全局样式已给，新页面不用再写）。该色**必须不透明**。症状（用半透明色如 `fill-0`）：横向滚动时，数据从固定在右侧的「操作」列表头下面透出来。
4. **操作列**：`dataIndex: 'actions'`、`fixed: 'right'`，并且 `<Table>` **必须设 `scroll.x`**（用 `tableScrollX(columns)`）。症状（没设 `scroll.x`）：`fixed` 不生效，窄了以后操作列跟着数据一起滚出视野。
5. **窄屏收成「…」**：用 `useActionsColumn(列设置之后的列, 每行→操作数组)`，返回的 `columns` 交给 `<Table>`；内部用 `TableActions` + `useCompactActions`。
   - **收起时机与「便捷搜索隐藏」是同一个断点**：视口 < 992px（`mediaDown('lg')`，样式里的 `--lg-down`），不按表格容器宽度判断——所有列表页一致。
   - 代价：992px 以上即使表格放不下，操作列也保持平铺、固定在右侧并横向滚动（会盖住一部分滚动中的数据）。这是有意的取舍（与便捷搜索同时切换，避免宽屏下操作被收进菜单）。
   - 收起后只显示「…」图标按钮（无文字，aria-label「更多操作」），列宽 `COMPACT_ACTIONS_WIDTH` = 52（按钮 24 + 内边距 24，取表头「操作」不折行的宽度）。
   - 只有一个操作（如操作日志的「详情」）时不收，直接渲染按钮。
   - 危险操作写 `confirm`：平铺时是 Popconfirm，收进菜单后自动改成 Modal.confirm。症状（菜单里直接挂 Popconfirm）：点了菜单项菜单就关了，确认框没有锚点，一闪而过。
6. **列宽预算**：1440 宽下最窄的是**双列菜单**布局，表格可用 **1115px**（侧边菜单 / 混合 1135，顶部菜单 1375）。列宽合计（弹性列按最小宽度计）控制在 1115 以内时，四种导航布局都不出横向滚动；超出时横向滚动（操作列固定在右侧），< 992px 时操作列收成「…」。
   - **固定列宽 = 内容宽 + 24**（单元格左右各 12 的内边距）。
   - 按**最坏数据**算，不要按样例：Inter 的数字不等宽（`1` 约 6px，`4` 约 8.3px），11 位手机号最宽约 91px → 列宽 **116**；`YYYY-MM-DD HH:mm:ss` 约 131.2px → 列宽 **158**（156 时小数宽度会把时分秒挤到第二行）；IPv4 最宽 `255.255.255.255` 约 104px → 列宽 **130**（操作日志原 120 会折行）。
   - 症状（按样例算）：`13800000001` 一行放得下，`13800000002` 就折成两行——只有部分行折，最难发现。
   - 普通文字列（用户名、昵称）可以压窄，超长时自然折行；**编号、手机号、时间不要折行**。
   - 改列宽后在真浏览器里量（`scrollWidth > clientWidth` 判溢出，`Range.getClientRects()` 判折行），不要只看单测。
7. **列设置**（`ColumnSettings`，偏好 `showTableColumnSettings`）：齿轮按钮 → 弹层勾选显隐、**拖放**调整顺序（每行左侧的把手；把手可聚焦，↑ / ↓ 同样移动），固定列与操作列不参与。不提供上移 / 下移按钮。

## 三、为什么集中写在这里

这些约定横跨 `SearchToolbar`、`TableActions`、`ColumnSettings`、全局样式和各列表页，单看任何一个组件的条目都拼不出全貌；
而它们的失败模式又都是「某个宽度 / 某份数据下才露出来、不报错」。新列表页照着用户页做，并逐条对照本文件。
